# Very Happy 视觉设计契约

> 状态：Active · 最后更新：2026-09-10
>
> 迁移执行与全量验收：[实施台账](../specs/2026-09-workspace-rollout.md)。本文件中较新的工作台标准覆盖早期相冲突的控件密度与加载描述；营销展示的字号层级独立。
>
> 适用范围：`packages/happy-web-v2` 的 Landing、登录/注册、App、弹窗与 PWA UI。
> 终端 pane 是结构性例外：两个主题下始终保持深色，并只使用 `--term-*` token。

本文件是视觉语义的事实源；具体色值的实现事实源是
`packages/happy-web-v2/src/styles/tokens.css`。两者不一致时先确认本契约，再同步 token，
禁止在组件里用裸色补丁绕过。

## 1. 风格与理由

- **主风格**：Bespoke；模式为 **Operate（操作）**。
- **视觉锚点**：现有 Landing 的黑白排版、细线分层、高反差 ink CTA，以及更新提示窗的
  纸面式信息层级。App 继承其材质、比例与控制权重，不复制营销页 Hero 构图。
- **配色策略**：Restrained（克制型）。中性色承担绝大多数层级，唯一彩色 accent 只表达实时状态。
- **成功标准**：用户先看到内容与当前任务，再看到控件；绿色只表示“活着、连着、运行着或被选中”。

## 2. 配色

亮色基准：`--bg-0: #f4f4f1`、`--text: #171715`、`--accent: #167d70`、
`--text-faint: #666762`。

暗色基准：`--bg-0: #111210`、`--text: #ecede8`、`--accent: #56b8a7`、
`--text-faint: #92958d`。

- `--bg-0..3`、`--line*`、`--text*` 构成普通表面和信息层级。
- 主 CTA、提交与发送使用 `--text` 填充和 `--bg-0` 前景；hover 只改变中性色阶。
- `--accent*` 只用于 connected、running、thinking、active/selected、focus 和实时拖放落点。
- 最大思考强度为 Owner 明确指定的彩色进度条例外：仅最高有效档的轨道填充使用 `--effort-max-gradient`，档位文字保持高反差，不把 off/default 显示成最大；不复用 live accent、不增加持续动画。
- 用户消息使用独立 `--message-user-bg/text`：亮色为低饱和灰蓝、暗色为深灰蓝，表达作者身份而非实时状态。气泡右对齐、四角一致（桌面 20px / 窄屏 18px），无描边与阴影；宽度随内容收缩，长文本断行，展开渐隐匹配同一底色。操作留在气泡下方，触屏展开按钮至少 44px。
- warn 只表达对应状态；组件 CSS/TSX 禁止裸色值。
- `--danger` = 错误与破坏性操作，**外加一处经审的扩展**：侧边栏「未读」徽点
  （`.sb-row-unread-dot`）。理由是 accent 已被 live 占死、warn 已被
  「等待授权」的状态点占死，红点=未读又是全行业公认语义；旧的 `--text` 白点
  与行内文字同色，Owner 用了数周都没发现这个功能存在（B-312）。除此之外
  `--danger` 仍然只表达 danger，新增用法要同样在这里登记。
- **次级信号别用 text 阶充数**：着色纪律把 accent 锁死给 live，于是「不够格用 accent」的标记
  很容易被顺手画成 `--text`——那是**行内文字自己的颜色**，等于不存在。B-312 的未读点这样活了
  几周，Owner 直接当成功能缺失来报。次级标记要么给它一个自己的色相，要么承认它不该存在。

## 3. 字体

- 标题：`IBM Plex Sans`，600–650，字号层级比至少 1.25，字间距 `-0.01em` 至 `-0.03em`。
- 正文：`IBM Plex Sans`，400，App 14–16px，行高 1.45–1.55；长文可到 1.7。
- 机器层：`IBM Plex Mono`，仅用于 session id、机器名、命令、路径、代码、时间戳、版本和度量值。
- 移动端可编辑控件使用 16px，避免 iOS 聚焦缩放；xterm 的专属几何与 16px 隐藏输入底线保持独立。
- 对话正文遵循下方紧凑工作台标准：桌面 14px / 1.6、触屏 15px / 1.6，顶层段落间隔 12px、列表项间隔 4px；标题前增加分组留白。命令内容复用 Shiki 双主题高亮，输出保持原文。输入区与对话共用背景，不使用顶部横线或外层卡片；输入框用相邻底色与轻微焦点边界区分，队列不另套卡片。输入框正文独占一行，工具和发送位于底部工具栏。＋、权限、模型/强度与单一主按钮始终在同一工具栏水平对齐；窄屏收起权限文字、最窄屏思考档在模型弹层查看，上下文已用百分比与已用/总容量 tokens 直接置于输入框下方，附件和预设放入＋菜单；排队消息贴合输入框上沿，调整方向与删除可直接操作。历史消息原位编辑，主按钮明确“在新分支中发送”，工具之间的中间回复不显示复制/引用。

## 4. 语调

- 控件使用短动词，直接说明动作，不写“欢迎使用”式空话。
- 状态和错误同时说明发生了什么，以及如何恢复。
- 中文使用全角标点；英文标题使用 sentence case。
- 版本、命令和机器信息保持具体，不使用“下一代、革命性、无缝”等营销套话。
- 手机主要动作至少 44px 高；需要连续操作的主按钮优先 48px。

## 5. 禁用范围

1. 不用绿色填充普通主 CTA、发送按钮或确认按钮。
2. 不用装饰性的紫蓝渐变、渐变文字、零偏移彩色光晕或大面积霓虹；最大思考档轨道遵循上面的明确例外。
3. 不用嵌套圆角卡片堆层级；优先表面台阶、间距和 1px 分隔线。
4. 不用超过 1px 的彩色装饰竖条；状态导轨必须有明确语义。
5. 不用多个无语义彩色强调色互相竞争。
6. 不用 mono 装饰普通标题或按钮。
7. 不用模糊/玻璃效果装饰普通 App 面板。
8. 不改变终端 pane 的 always-dark 规则。
9. **不把「第二段对话」原地展开进主对话流**：子代理卡（B-317）、诊断输出这类
   自成一段的内容，展开后是几十行写给机器看的文字夹在用户自己的两段话之间，
   读起来像 UI 坏了。对话流里只留**一行指针**（是谁 / 在做什么 / 多久），
   正文进 session aside 抽屉（`.sd-files` 那一格，窄屏自动变整屏 + scrim）。
   判据是「这段内容有没有自己的时间线」——有就该有自己的容器。

## 实现检查

- Landing、更新窗、登录和 App 的 primary action 使用同一套 ink/canvas 关系。
- 绿色面积随实时状态数量变化，而不随可点击控件数量变化。
- focus 必须可见；触屏命中区和 16px 输入字号不得因视觉收敛退化。
- 两个主题、390px 手机宽度和桌面宽度都不得出现横向页面滚动。
- 带变换或装饰溢出的交互图，点击并聚焦内部按钮后也须检查外层容器的 `scrollLeft`；
  `document.documentElement.scrollWidth` 没有溢出不能证明页面没有横移。首页由文档负责纵向滚动，
  `.pub-page.pub-landing` 使用 `overflow: clip visible`；`clip auto` 会计算成
  `hidden auto`，使聚焦能够横向滚动装饰内容。此修复仅限首页，不套用到其他滚动容器。
- 新组件优先复用 `vh-*` 与 token；新语义 token 先更新本契约和 `tokens.css`。

### 会话实时状态

- 当前活动名称用 Sans，耗时/token 用 Mono；输入 ↑、输出 ↓ 与消息尾部一致，缓存独立，思考量加 ≈，不把估算当精确输出或相加。
- 数字只跟随真实上报；普通状态“处理中”，不用初始 output token 推断正文阶段。只让状态名称进入 aria-live，计时与计量不逐秒播报。
- 整屏启动遵循下方品牌连接图标准；对话内使用 18px 单轨迹与呼吸核心，沿用连接意象。动画只改变 transform/opacity，减少动态效果时静止。
- 实时计量固定单行：输入/输出直接展示，缓存与思考等明细点击展开。长工具名省略但详情保留完整名称，详情仅在用户点击后于正文内展开，避免被滚动区域裁切；计时和流式更新不改变收起行的高度。

## 材料状态

- Logo：已具备现有产品资产。
- 产品截图：已具备 Landing 内现有产品预览；本契约不要求新增图片。
- 品牌色：从现有 phosphor teal 提取，降级为实时状态色。
- 字体：已具备 `IBM Plex Sans` / `IBM Plex Mono` 与系统后备。

## Teams 对外表达

完整功能名为 **Very Happy Teams**，英文界面简称 **Teams**，中文入口为 **团队**。
Happy Bot 保留在历史记录与搜索别名中；既有设置键无需随显示名迁移。
整体定位为 **coding agent hub**：连接不同机器与 agent，随时随地接续工作。
首屏主张为 **Every machine. Every agent. Anywhere.**，先让用户理解在哪里运行、
从哪里访问；Teams 再解释如何组织多个 agent 一起工作。
首页首屏与 README 主视觉使用机器／agent 汇聚图；紧接着用 Teams 协作图解释
「目标 → 负责人 → 并行成员 → 提交与验收」。Teams 是核心协作能力，不代替产品整体定位。
首屏主入口连接第一台机器，次入口跳到 Teams 第二节；该节再进入团队使用教程。
普通对话和终端是完整的使用路径，不以创建团队作为前置步骤。
公开文档先给出平台全貌，再介绍 Teams；团队当前仍是单账号、单执行电脑范围。
多机器接入不等于一个团队已支持跨机器自动调度，宣传与架构图须保留这一边界。

协作图必须标明示例，不能把演示状态伪装成用户实时数据。
负责人和成员用动作与任务区分；绿色只用于运行状态与允许的交互状态。
营销主标题使用实色和正常行距；不以旧语音协调器代表 Teams。

## 紧凑工作台标准 v1（已发布，2026-09-10）

本节是 Owner 已确认并随 PR #320 发布的统一设计标准；所有新 UI 和重构按此实施。开发预览入口为
`/dev/workspace-design`，只在开发模式提供，所有会话、用量与交互均为本地示例。
实现/评审范围见 [工作台设计提案](../specs/2026-09-compact-workspace-design.md)。

### 设计契约

- **风格**：Bespoke / Operate / Restrained。首要锚点是 Owner 提供的 Codex 完整工作区截图：
  单行项目会话列表、低高度顶栏、正文优先、贴近画布的输入区。辅助锚点为编辑器文件树的
  层级缩进与工作日志的紧凑时间线。保留 Very Happy 的实时状态语义。
- **配色**：沿用 token：亮色 canvas `#f4f4f1`、ink `#171715`、muted `#666762`、
  accent `#167d70`；暗色 canvas `#111210`、ink `#ecede8`、muted `#92958d`、accent `#56b8a7`。
  项目侧栏为相邻表面，选中任务只用中性底色和字重；实时/未读沿用现有语义。
  侧栏与正文只画一道 1px 分隔线，拖拽命中区与描线分开；底部工具区用留白分区，不再叠加横线。
  导航、会话行与底部工具共享左右 8px 外留白及 8px 内留白；辅助徽标保持低对比，排序说明按需展开。
- **字体**：继续使用已有 IBM Plex Sans，避免另载字体与无关品牌变化。主要导航、会话名与正文以 14px 为基准（次级控件 13px / 1.5），
  正文桌面 14px / 1.6，触屏 15px / 1.6，辅助 11–12px。Mono 仅用于代码、路径与度量。
  输入控件触屏与窄屏统一 16px。标题用 600 字重，普通任务不用粗体。
- **语调**：短动作；状态明确；示例必须标明；不把实现或性能口号放进产品正文。
- **禁用**：不堆卡片、不双层描边、不用大空白占据工作区、不重复展示状态、
  不常驻成排次要操作、不用全局缩放伪装紧凑、不缩小触屏命中区、不隐藏关键状态。

### 尺寸与信息分工

| 元素 | 桌面 | 触屏 / 窄屏 |
|---|---|---|
| 侧栏 | 初始宽 260px；项目可折叠；任务行 32px | 抽屉；任务行 44px，菜单始终可见 |
| 顶栏 | 44px；标题、少量全局操作 | 标题优先；保留返回/导航与必要操作 |
| 正文 | 14px / 1.6；段落间距 12px；列表内 4px | 15px；长路径断行，代码局部滚动 |
| 消息节奏 | 消息间距 18px；工具行 28px | 消息间距 16px；可点击工具区至少 44px |
| 输入区 | 初始文本区约 50px，随内容增长；底部单行工具栏 | 16px 输入字体，主控件 44px |
| 框下信息 | 上下文占比、已用/容量直接展示；快捷键提示靠右 | 保留用量，省略键盘提示 |

### 材料与验收

- 参考截图：Owner 提供的 Codex 全页截图；不按截图物理像素复制字号。
- 品牌、字体、图标：使用现有 Very Happy 名称、字体与 Lucide。
- 预览数据：显式示例，不读取或改写真实会话，不发送模型请求。
- 验收：明暗主题、1280/1440 桌面、390/320 手机；项目折叠/搜索/选中、主题切换、
  长输入、排队/停止、快捷指令、最大强度彩条、键盘焦点与横向溢出。
- 设计确认后分区域接入真实数据，保留既有排序、权限、消息与发布协议；不借视觉改版更改业务语义。
- 响应式断点和侧栏折叠只调整布局，不重建当前页面或笔记宿主；未提交的表单、当前子页与阅读位置应保留。路由内容保持稳定的 React 层级和 key，不能在桌面/手机分别复制 Outlet。

### 工作台预览补充（2026-09-10）

- 常用入口不得因视觉收敛消失：侧栏常驻帮助、团队、待办、终端；帮助保留整页，快捷指令放输入区＋菜单并在设置中管理。
- 设置用分类导航、可搜索的分组行与右侧控件；手机分类切换与搜索仍可达。
- 控件聚焦不画外侧 outline 或 glow，键盘 focus-visible 使用局部底色/字色反馈；保留可辨识的键盘焦点。
- 下拉、右键、权限、快捷指令和语言菜单的 hover／键盘高亮统一使用整行 `--bg-3`，不叠加底部焦点线；分隔线只用于菜单分组。
- 手机输入、搜索、选择控件统一 16px，同时使用窄屏和 coarse 条件覆盖；不依赖浏览器缩放修复布局。

### 实时性与品牌（工作台预览第三轮）

- 会话标题旁与侧栏保留现有 CyberMark 微笑终端 Logo；沿用暖灰画布、深色墨黑表面和青绿实时信号，不复制 Codex 的品牌图形或配色。
- 会话元信息直接显示驱动 Agent（Claude Code / Codex / Pi 等），与模型选择分开。正式实现只从会话上报读取，不从模型名字推断；缺失显示未知。
- 流式内容贴底自动跟随。用户上翻时暂停，回到最新后恢复；同一消息持续变长、工具输出长高、容器高度变化均需覆盖，不能只监听消息条数。
- 实时状态位于正文末尾，随正文滚动，收起时保持单行高度，无卡片、无布局动画；直接展示当前阶段/工具名，不强迫用户展开才知道工具在运行。耗时和输入/输出计量紧凑展示，缓存/估算思考等详情按需展开；窄屏仍不换行。
- 无状态时不保留空槽，也不挤占输入区域；状态开始/结束按现有贴底规则跟随，上翻阅读时不抢滚动位置。长工具名只省略文字，完整名称在详情可读。减少动态效果时关闭呼吸动画。

### 入口完整性（工作台预览第四轮）

侧栏主导航收敛为新建、搜索与命令、团队、待办、帮助；底部保留设置、快捷笔记与主题。
终端不作为与团队同级的额外按钮，普通对话/终端/指定目录/接入 tmux/导入历史统一放入新建。
旧终端快速快捷键保持语义。运行概览移出常驻导航，仍保留待处理聚合与最近完成能力。
会话工具保留文件、笔记、组建团队、侧问等能力；relay 区域仍直接可见。
完整保留矩阵和未接入项见 [入口走查](../specs/2026-09-workspace-entry-audit.md)。

### 列表管理与更新反馈（第五轮）

主题切换只在侧栏底部，不在会话顶栏重复。项目列表标题旁提供展示方式菜单；项目、标签、
不分组都要可达。标签可从会话菜单编辑；不分组时可拖拽排序，键盘/触屏有菜单排序替代。
更新提醒放在侧栏底部；详情沿用统一的中性表面、品牌标识和清晰版本层级。
Changelog 的显式确认与关闭分开，保留历史入口、跨版本信息及 CLI 升级提示。

## Logo 使用标准（2026-09-10）

唯一图形为现有「微笑终端」：提示符左眼、方块右眼、微笑与圆角外框。源资产为
`public/icon-192.png` / `icon-512.png`，单色矢量实现为 `ui/CyberMark.tsx`，不另画替代图案。

| 场景 | 版本与尺寸 | 规则 |
|---|---|---|
| 侧栏品牌入口 | 透明单色 CyberMark 24px + Very Happy 14px/600 | 两者间距 8–10px，点击回帮助；整页只放一组主品牌 |
| 会话标题栏 | 单色 CyberMark 18–20px | 不再重复品牌全名；侧栏收起时仍可辨识产品 |
| 设置/帮助/更新内容 | 单色 24–32px | 用于页面身份或更新标题，不给每张卡片加 Logo |
| PWA/网站图标 | 现有完整彩色栅格资产 | 保留固有深色底与青绿图形，不用 CSS 重新着色 |
| 大型加载展示 | 既有 OrbitLoader | 活动动画与 Logo 分开，不旋转/变形 Logo 本体 |

- 始终保持 1:1 比例，四周净空至少图标宽度的 1/4；不得拉伸、裁切或改变眼睛/微笑比例。
- 单色版只使用主题 `--text`，随明暗主题切换。彩色图标自身品牌色是资产身份，不代表运行状态；控件仍遵守 accent 的实时语义。
- 不增加阴影、发光、渐变底、描边圈、动画或自制反白色板；点击目标手机至少 44px，图标无需放大到 44px。
- 语音助手四态共用静止 CyberMark：待机无光晕，聆听音量环、思考弧线和朗读波形放在独立层；不缩放 Logo、不添加圆形底框或状态光框。手机操作维持 44px，语音执行和麦克风权限不因视觉改版变化。
- 与“Claude Code / Codex / Pi”身份分离：产品 Logo 不代表后端 agent，模型名称也不替代 agent 身份。
- 有文字品牌时图形装饰性 aria-hidden/空 alt；只有图标的交互入口必须提供明确可访问名称。

## 右侧工作区标签

文件目录、多个文件预览、改动、快捷笔记、运行概览与浏览器预览使用同一个右侧工作区。
桌面三栏并排，对话拥有独立滚动；不再为每项长期辅助内容弹出独立模态卡片。
默认右栏约 36vw、最少 320px；总宽不足 1100px 时转为全屏面板，关闭回到原对话。

- 单实例工具重复打开激活已有标签；不同文件按路径区分。标签支持选中、关闭、键盘左右/Home/End。
- 切换标签保留草稿、各自滚动位置；当前会话内收起整个面板保留挂载内容，隐藏时不抢焦点或拦截键盘。切换会话/终端身份释放旧视图，关闭具体标签释放该标签，关闭最后一个内容标签时收起面板；跨整页导航仅恢复各功能明确保存的视图信息，不承诺外部网页运行状态。
- 标签过多时横向滚动，不把标签挤成无法点击的图标；手机关闭目标至少 44px。
- 激活标签只调整标签栏自己的横向滚动，不能使用会滚动祖先的 scrollIntoView；嵌入 Landing/文档的工作台展示不得在挂载时抢走整页阅读位置。
- 所有工作区标签仅保留关闭按钮，不展示“更多”图标或移动菜单。鼠标拖拽排序，键盘 Alt+Shift+左右箭头作为等价操作；hover/focus 只改变颜色，不新增图标、不改变宽度或推挤相邻标签。关闭和拖拽落点均不能引发布局跳动。
- 标签必须关联真实 session/workspace 身份。切换会话不得把旧文件冒充新目录；生产迁移时保存/恢复各自工作区。
- 笔记草稿不因关闭标签丢失，真实同步/保存失败沿用现有机制。文件/改动保留路径与只读/可编辑状态。
- 新建、审批、删除确认等短事务仍可使用模态框；不能为了“所有东西都在右侧”隐藏关键审批。
- 浏览器预览是专门能力：需要处理目标地址、远端端口、嵌入策略、加载失败与导航。生产工作区提供用户输入 URL 的沙箱 iframe、刷新和外部打开；不声称任意站点都能嵌入，不自动代理远端 localhost。原型中的浏览器示意仍不访问网址。

## 面板栏与系统状态（第七轮）

- 右侧仅保留一条标签栏；新增标签、收起与标签切换同排，不叠加“工作区”标题栏。
- 机器名、Agent、relay 区域放会话顶栏，正文不额外占一行元信息。窄屏压缩非主要图标与长名称，完整信息保留详情；对话标题必须仍有可读空间。
- 启动状态：使用 Very Happy 静止微笑终端 Logo 作为连接中心，四周为 Agent、终端与工作空间，细连接线轻脉冲。保留多 Agent 汇聚的品牌意象，去掉满屏网格与旋转卡片；不用假百分比。连接图表达产品身份，不代表各服务已连接；真实进度仅由状态文字表达。读取真实主题，避免加载前后闪色。
- 路由加载：保留导航与输入区尺寸，正文显示静态骨架和单行状态；不用全屏品牌动画遮挡已有工作。
- 空状态：说明下一步并提供一个主要动作；不要只写“暂无数据”。
- 加载失败：保留旧内容和草稿，给出重试/返回；不得自动清空会话或承诺未验证的恢复结果。
- 断线恢复：轻量行内提示，保留阅读和草稿；继续沿用唯一 resumeSync 恢复通路，不另造轮询或重连策略。
- 权限等待：请求、操作内容与明确选择保留在对话可见区域，不能隐藏进普通标签；视觉与状态模型分开，审批能力门控保持。
- 减少动态效果时活动条与脉冲静止，所有状态有文字说明；不得依赖动画单独表达状态。

正式接入首屏需同时更新 index.html 预绘制与 RouteLoading，并保留现有移除时机、超时恢复、失败回退与主题来源，不能只替换 React loading。
首屏预绘制与 React 加载共用品牌图形、样式及主题读取；`/dev/workspace-design` → 会话工具 → 界面状态仍用于查看其他状态原型。


### 终端、右键与拖拽（第八轮交互提案）

- 终端 session 在同一会话列表中用终端图标区分，顶栏保留机器、目录、连接状态。终端始终深色；Agent 输入与终端键盘输入是独立模式，不能用普通消息发送假装写入 PTY。
- 会话行右键与省略号共用菜单：重命名、标签、排序、归档等按实际能力展示。终端菜单明确区分关闭视图、断开连接和结束进程；结束进程须明确确认，不能把关闭标签绑定到杀进程。
- 文件与右侧标签可右键：复制路径、打开、关闭当前/其他标签等仅对有效对象可用。菜单跟随点击位置并避开屏幕边缘，Escape/外点关闭、关闭后还原焦点，键盘菜单键可打开；文件行触屏保留可见省略号替代；工作区标签只保留常驻关闭按钮，不增加省略号。
- 不拦截正文、输入框或终端选区的原生右键与长按复制。终端粘贴需走现有权限和剪贴板机制，不能右键即执行命令。
- 拖拽会话只在手动排序有效的视图启用；分组视图不得无意改项目归属。标签拖拽仅改变标签顺序，不复制会话。两者都显示插入落点；会话列表保留菜单移动替代，工作区标签使用 Alt+Shift+左右箭头，不增加移动菜单或操作图标。
- 文件拖入输入框表示添加附件，提交前展示列表和移除入口；拖到预览区表示打开预览。不得因拖入终端自动上传/执行，未支持目标显示不可放置。
- 右栏宽度可用分隔条调整，设置最小正文宽度；手机用全屏面板，不提供难操作的分栏拖柄。持久化、会话隔离、断线/重连/只读/进程结束状态均需在正式迁移时验收。
- 真实会话列表、工作区标签和终端已接入本地实现，功能覆盖与边界见实施台账；设计示例不作为真实运行证据。文件拖放只在已支持的目标生效，不以此标准承诺任意文件跨机器传输或终端执行。

### 手机登录页

登录表单在可用视口内水平、垂直居中；用自动外边距吸收剩余空间，内容超过屏幕时从安全区顶部开始滚动，不得裁切顶部。软键盘展开时沿用 visualViewport 固定高度，解除 min-height 限制并取消垂直自动外边距。手机登录去掉外层阴影/玻璃卡片，保留微笑终端品牌、语言、所有登录方式与帮助法律入口；输入字号 16px、主要操作至少 44px。

注册页遵循相同的手机表面和居中规则，邀请码、关闭注册与容量提示仍可达。触屏初次打开登录/注册不主动聚焦输入，用户请求验证码后的聚焦继续保留；品牌 Logo 在注册、配对和空状态中同样不加发光。


## 公共页面的品牌表现（已确认）

Landing、文档入口、登录与整屏启动承担品牌识别，不使用工作台紧凑字号压缩营销标题。
保持醒目的排版、Very Happy 微笑终端、机器/Agent 汇聚与有节奏的动效；主题、字族、按钮与基础材质保持统一。允许有语义的连接图与局部背景纹理，不以整页廉价光晕替代设计。
截图必须来自本次真实实现的页面（示例数据需标注），覆盖会话/终端/团队与移动端；文档站、Landing 与 README 共用经过审阅的资产，不能保留旧界面冒充新版。
更新通知允许使用 Owner 指定语气：“直接抄一手 Codex UI，这个最好看嘿嘿。”同时明确真实变化与 Very Happy 自有能力，不宣称未完成的功能。

### 工作台反馈修复（B-435）

搜索使用侧栏品牌行的独立按钮，保留 Cmd+K；新建会话菜单与整行触发器左对齐且至少等宽。
正文与输入框共用完整会话列的 820px 对齐基准（桌面内边距 16px、窄屏/coarse 12px），正文宽度不能按扣除滚动条后的宽度居中。运行状态跟随正文末尾，不使用固定输入区状态槽。文件入口默认目录浏览，可展开文件树、筛选已加载文件；宽度足够时树与带行号的预览并排，窄面板返回目录保留展开位置。
Pi 框下上下文使用运行时当前估算与真实容量，前缀 ≈；未知使用 —，不拿累计用量补值。团队顶部提供归档，后台取消与保留语义见 [修复 spec](../specs/2026-09-workspace-followup.md)。

### 新手引导与操作反馈（B-436）

首次使用优先连接机器；常驻帮助把连接入口放主操作，并说明执行电脑、relay、手机与 Agent 的分工。官方 skills 按团队、内置待办、外部 provider 区分，不暗示安装即授权或接管。运行列表用右侧紧凑 Spinner，等待/未读保留各自语义；减少动态效果时静止。新建与发送的异步状态必须在原操作位置可见，不加假延时或百分比。折叠屏除了页面视口，还参考实际屏幕宽度；布局与浮层采用同一条件，切换不得重建当前表单。

### 团队启动（B-438）

创建以目标输入为中心，复用最近电脑/项目并在配置摘要中明确显示，未知配置展开选择；高级选项可修改，不把选择表单铺满首屏。启动等待沿用发送处 Spinner，成功进入负责人的真实对话。无 session 的成员仍显示名称和“准备中/需处理”并链接任务详情；启动错误在任务详情就近显示，不藏在整页底部。

### 目录内新建（B-446）

工作目录分组标题旁常驻新建加号，与查看改动按钮同排，hover 不改变宽度；触屏命中区 44px。
快速新建优先使用显式目录，其次当前路由会话/终端的机器与原始目录，无上下文才使用最近记录。
目标离线或目录未知时打开配置并保留预填，不静默换机器；始终询问配置的设置仍生效。

### 文件预览操作（B-447）

会话文件入口使用文件夹图标，默认目录浏览。弹窗与右侧文件页共用预览和操作：下载原始文件、复制路径、复制完整文本；未加载完整文本时不把片段标成完整复制。弹窗可固定到当前同机器工作区，路径保持从左到右，不改真实路径字符。
表格采用本地只读网格、工作表切换和分页，不外传文件；边界与格式限制见 [文件预览 spec](../specs/2026-09-file-preview-actions.md)。窄面板路径与操作分两行，图标始终占位，触屏操作至少 44px。

### 右侧工作区画布与接缝（B-448）

对话、右侧工作区和右侧拖拽命中区共用 `--bg-0`，分隔仅用一条 1px `--line`；不能用亮色拖拽带或卡片底色割裂正文。文件树、预览和工具条继承宿主表面，弹窗保留自身 `--bg-1`；左侧导航保持相邻面板层次。标签选中用 `--bg-2`，不因统一画布失去选中反馈。

文件代码预览与路径栏共用宿主画布：取消代码高亮自身底色和外层重复留白，只保留代码内部阅读间距。此规则仅用于独立文件预览，不改变聊天代码卡片及其折叠渐隐。

### 右侧工作区收敛（B-451）

工具从标签栏的＋菜单打开；已打开文件、笔记、侧问和浏览器继续使用统一标签，选中态为中性圆角底色，不再逐个画竖线。关闭按钮始终占位，拖拽与键盘排序保留。笔记正文使用对话字号和行高 token，移动端编辑仍为 16px。侧问不重复顶部说明行，边界说明放空状态和输入工具行。

面板切换只允许 140ms 轻量淡入，不位移、不缩放、不动画布局；减少动态效果时禁用。正文运行状态 hover 保持透明，仅字色和固定箭头变化，键盘焦点有内侧边界，展开时箭头转向。

### 统一 Agent 状态（B-452）

侧栏左侧只表达会话类型：UI 对话与 Claude/Codex/Pi 终端均用中性灰符号，名称进入可访问标签。右侧固定一个 16px 状态位，依次呈现等待操作（warn）、运行转圈、未读红点、离线/状态未知；空闲留空。移除状态点光晕和左侧彩色副点。未知不等于空闲，未读独立保存。侧栏与状态列表共用新鲜度判定，终端观察不依赖单纯有输出或进程存活。

侧栏品牌栏和对话 header 不再显示独立连接圆点；对话连接信息由中继 tag 承载，避免与会话行的 Agent 状态重复争夺注意力。

正文活动状态采用紧凑行：活动名称、分隔点、耗时和展开箭头相邻排列，token 明细只在展开后显示；hover 不改变画布底色。同一轮内连续完成的 Terminal 命令折叠为带数量和最后一条命令摘要的组，展开仍保留各条命令及输出；不跨正文、其他工具、运行中或失败命令分组。
