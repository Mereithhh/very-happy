# Very Happy 视觉设计契约

> 状态：Active · 最后更新：2026-08-27
>
> 适用范围：`packages/happy-web-v2` 的 Landing、登录/注册、App、弹窗与 PWA UI。
> 终端 pane 是结构性例外：两个主题下始终保持深色，并只使用 `--term-*` token。

本文件是视觉语义的事实源；具体色值的实现事实源是
`packages/happy-web-v2/src/styles/tokens.css`。两者不一致时先确认本契约，再同步 token，
禁止在组件里用裸色补丁绕过。

## 1. 风格与理由

- **主风格**：Bespoke；模式为 **Operate（操作）**。
- **视觉锚点**：现有 Landing 的黑白排版、细线分层、高反差 ink CTA，以及更新提示窗的
  纸面式信息层级。App 继承其材质、比例与控制权重，不复制营销页 Hero 构图。
- **配色策略**：Restrained（克制型）。中性色承担绝大多数层级，唯一彩色 accent 只表达实时状态。
- **成功标准**：用户先看到内容与当前任务，再看到控件；绿色只表示“活着、连着、运行着或被选中”。

## 2. 配色

亮色基准：`--canvas: #f4f4f1`、`--ink: #171715`、`--accent: #167d70`、
`--muted: #666762`。

暗色基准：`--canvas: #111210`、`--ink: #ecede8`、`--accent: #56b8a7`、
`--muted: #92958d`。

- `--bg-0..3`、`--line*`、`--text*` 构成普通表面和信息层级。
- 主 CTA、提交与发送使用 `--text` 填充和 `--bg-0` 前景；hover 只改变中性色阶。
- `--accent*` 只用于 connected、running、thinking、active/selected、focus 和实时拖放落点。
- warn、danger 只表达对应状态；组件 CSS/TSX 禁止裸色值。

## 3. 字体

- 标题：`IBM Plex Sans`，600–650，字号层级比至少 1.25，字间距 `-0.01em` 至 `-0.03em`。
- 正文：`IBM Plex Sans`，400，App 14–16px，行高 1.45–1.55；长文可到 1.7。
- 机器层：`IBM Plex Mono`，仅用于 session id、机器名、命令、路径、代码、时间戳、版本和度量值。
- 移动端可编辑控件字号不得小于 16px，避免 iOS 聚焦缩放。

## 4. 语调

- 控件使用短动词，直接说明动作，不写“欢迎使用”式空话。
- 状态和错误同时说明发生了什么，以及如何恢复。
- 中文使用全角标点；英文标题使用 sentence case。
- 版本、命令和机器信息保持具体，不使用“下一代、革命性、无缝”等营销套话。
- 手机主要动作至少 44px 高；需要连续操作的主按钮优先 48px。

## 5. 禁用范围

1. 不用绿色填充普通主 CTA、发送按钮或确认按钮。
2. 不用紫蓝渐变、渐变文字、零偏移彩色光晕或大面积霓虹。
3. 不用嵌套圆角卡片堆层级；优先表面台阶、间距和 1px 分隔线。
4. 不用超过 1px 的彩色装饰竖条；状态导轨必须有明确语义。
5. 不用多个无语义彩色强调色互相竞争。
6. 不用 mono 装饰普通标题或按钮。
7. 不用模糊/玻璃效果装饰普通 App 面板。
8. 不改变终端 pane 的 always-dark 规则。

## 实现检查

- Landing、更新窗、登录和 App 的 primary action 使用同一套 ink/canvas 关系。
- 绿色面积随实时状态数量变化，而不随可点击控件数量变化。
- focus 必须可见；触屏命中区和 16px 输入字号不得因视觉收敛退化。
- 两个主题、390px 手机宽度和桌面宽度都不得出现横向页面滚动。
- 新组件优先复用 `vh-*` 与 token；新语义 token 先更新本契约和 `tokens.css`。

## 材料状态

- Logo：已具备现有产品资产。
- 产品截图：已具备 Landing 内现有产品预览；本契约不要求新增图片。
- 品牌色：从现有 phosphor teal 提取，降级为实时状态色。
- 字体：已具备 `IBM Plex Sans` / `IBM Plex Mono` 与系统后备。
