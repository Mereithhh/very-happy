# Very Happy 视觉设计契约

> 状态：Active · 最后更新：2026-10-13
>
> 迁移执行与全量验收：[实施台账](../specs/2026-09-workspace-rollout.md)。本文件中较新的工作台标准覆盖早期相冲突的控件密度与加载描述；营销展示的字号层级独立。
>
> 适用范围：`packages/happy-web-v2` 的 Landing、登录/注册、App、弹窗与 PWA UI。
> 终端 pane 是结构性例外：两个主题下始终保持深色，并只使用 `--term-*` token。

本文件是视觉语义的事实源；具体色值的实现事实源是
`packages/happy-web-v2/src/styles/tokens.css`。两者不一致时先确认本契约，再同步 token，
禁止在组件里用裸色补丁绕过。

## 1. 风格与理由

- **主风格**：Bespoke；模式为 **Operate（操作）**。
- **视觉锚点**：现有 Landing 的黑白排版、细线分层、高反差 ink CTA，以及更新提示窗的
  纸面式信息层级。App 继承其材质、比例与控制权重，不复制营销页 Hero 构图。
- **配色策略**：Restrained（克制型）。中性色承担绝大多数层级，唯一彩色 accent 只表达实时状态。
- **成功标准**：用户先看到内容与当前任务，再看到控件；绿色只表示“活着、连着、运行着或被选中”。

## 2. 配色

亮色基准：`--bg-0: #fcfcfb`（画布）、`--text: #171715`、`--accent: #167d70`、
`--text-faint: #5f605b`。

暗色基准：`--bg-0: #151515`（画布）、`--text: #ecede8`、`--accent: #56b8a7`、
`--text-faint: #9a9d95`。

- 表面、边框与阴影按下方「§2.1 表面、边框与层级」的 CDS 阶梯；`--text*` 构成信息层级。
- 主 CTA、提交与发送使用 `--text` 填充和 `--bg-0` 前景；hover 只改变中性色阶。
- `--accent*` 只用于 connected、running、thinking、active/selected、focus 和实时拖放落点。
- 最大思考强度为 Owner 明确指定的彩色动效例外：仅最高有效档使用 `--effort-max-gradient` 的流动轨道与能量扫光，档位文字保持高反差，不把 off/default 显示成最大；不复用 live accent、不改变布局，不使用强闪烁。遵循本次确认的持续动态效果，系统减少动态效果时显示静态彩条。
- 用户消息使用独立 `--message-user-bg/text`：亮色为低饱和灰蓝、暗色为深灰蓝，表达作者身份而非实时状态。气泡右对齐、四角一致 18px（`--r-bubble`）、内边距 10/16，只有底色、无描边与阴影；宽度随内容收缩，长文本断行，展开渐隐匹配同一底色。操作留在气泡下方，触屏展开按钮至少 44px。
- warn 只表达对应状态；组件 CSS/TSX 禁止裸色值。
- `--major` / `--major-dim`（B-715）只表示「大更新」：更新通知、`/changelog`、`/whats-new` 的大更新徽标与侧栏「大更新 · N 条未看」入口。紫色，亮暗各一套，文字满足 AA；不表达状态，不用于其他强调。
- `--search-hit`（B-650）只表示搜索命中：会话搜索结果里的 `<mark>` 与跳转后对话里的命中高亮（`::highlight(vh-search-hit)`）。低饱和黄底、文字保持 `--text`，不表达状态，不用于其他强调。
- `--danger` = 错误与破坏性操作，**外加一处经审的扩展**：侧边栏「未读」徽点
  （`.sb-row-unread-dot`）。理由是 accent 已被 live 占死、warn 已被
  「等待授权」的状态点占死，红点=未读又是全行业公认语义；旧的 `--text` 白点
  与行内文字同色，Owner 用了数周都没发现这个功能存在（B-312）。除此之外
  `--danger` 仍然只表达 danger，新增用法要同样在这里登记。
  B-552：⌘K「等我看」行尾复用同一状态位（`.cp-status-dot`），语义同为「未读」，不算新用法。
- **次级信号别用 text 阶充数**：着色纪律把 accent 锁死给 live，于是「不够格用 accent」的标记
  很容易被顺手画成 `--text`——那是**行内文字自己的颜色**，等于不存在。B-312 的未读点这样活了
  几周，Owner 直接当成功能缺失来报。次级标记要么给它一个自己的色相，要么承认它不该存在。

## 2.1 表面、边框与层级（CDS，B-614）

Owner（2026-10-16）：「各种细节你抄一下这个项目里面的设计准则。方框卡片里面包着一层卡片，我觉得这个是非常怪的。」
来源是 open-claude-ui 的 CDS 文档（docs/v1/01 §1.2–1.6、02、03 §3.1–3.3、08 §8.4、code-examples/cds-theme.css）。我们只采纳规则，色值用自己的 token 实现，不照搬 CSS。
两处来源互相矛盾时，以 01 §1.2 和 cds-theme.css 为准。
品牌项保留：`--accent` 只表示 live，主 CTA 用 ink/canvas，字体用 IBM Plex，终端 pane 恒为深色，全部文字满足 AA（比 CDS 更严：它的 tertiary 不达标），保留对话字号设置。

**1-Border Rule（最高优先级）**：从画布向内的任何一条视线上，最多只能穿过一道闭合边框（4 边 border、0 模糊的 ring 或 outline）。闭合容器内部不再出现闭合边框，只能用填充台阶、单边 hairline、ghost 或 soft-fill 控件。检查：dev server 起着时跑 `node scripts/dev/nesting-audit.mjs --base <url>`（审 dev harness 的对话、输入区、侧栏、右侧面板、团队页，明暗两套），目标 0 违规。

| 元素 | 处理 |
|---|---|
| 助手正文、思考头与展开的思考、回合摘要、工具行、工具组、子代理行、Codex 子线程行、事件行、消息操作栏、侧栏行、状态胶囊 | **无边框**。行用 ghost hover（`--fill-hover`），选中用 `--fill-selected`，胶囊只有填充。工具组外面**不套卡片**。 |
| 用户消息 | 只有填充（`--message-user-bg`），圆角 18，内边距 10/16。 |
| 展开的工具输出（命令、文件、diff）、代码块、表格 | 行下面这一个对象就是唯一的闭合物：圆角 12（表格 10），`--panel-shadow`（1px 环 + shadow-sm），代码槽比画布更深（`--surface-code`）。工具行仍是对象上方的一行无边框标题，**不用卡片包住标题和内容**。语言栏、文件名、统一/分栏切换都是条带，只用一条 hairline 分隔，没有自己的框。 |
| 输入框 | 唯一闭合物：`--surface-raised`，圆角 20，三态阴影（静止 / hover / focus-within：`--shadow-composer*`）。内部全部无边框（ghost 或 soft fill）。 |
| 权限卡、团队消息卡、会话互发卡、附件磁贴、团队页任务卡 | 各自一个闭合物：圆角 10（磁贴 12），`--panel-shadow`；权限卡和冲突卡用 warn 色环。内部的命令预览只有填充，头部条用 hairline 分隔（可以有填充，不能有框），次级按钮用 soft fill。 |
| 弹窗、菜单、浮层、toast、命令面板 | 一个闭合物，用 `--shadow-popover`：亮色是外 1px 环 + 柔投影，暗色是内 1px 倒角 + 投影、没有外环。菜单行高亮圆角 6，分组用 hairline。 |

需要切换状态的东西，边框优先画成 `box-shadow` 环，避免 1px 抖动。
**例外说明**：暗色模式下，流内的闭合物沿用 cds-theme.css 的外侧 9% 白环；内倒角只用于浮层，因为流内对象的头部填充会盖住内环。

**表面阶梯**：`--surface-sidebar`（surface-0，侧栏，低于画布：暗 #0b0b0a / 亮 #f5f5f3）→ `--bg-0` 画布（#151515 / #fcfcfb）→ `--bg-1` 卡片、面板、弹窗、菜单（#1a1a19 / #fff）→ `--surface-raised`、`--surface-popover`（#20201e、#222220 / #fff）。
另有 `--surface-code`，是比画布更深的代码槽（#0d0d0c / #f5f5f3）。`--bg-2` 和 `--bg-3` 是填充台阶（输入、chip、hover-on-bg-1、按下态）。
**Alpha 阶梯**（亮色用墨，暗色用白）：`--fill-hover` 5%、`--fill-selected` 和 `--line` 10%（暗 9%）、`--fill-soft` / `--fill-soft-hover`、`--line-2` 20%（暗 18%）、`--line-heavy` 35%（暗 30%）。
画面的丰富感来自真正需要对比的地方（侧栏与画布、输入框、代码槽、用户气泡、浮层），以及去掉多余的框，而不是把每样东西都框起来。

**阴影**：`--shadow-sm/md/lg`（暗色同样的几何，0.4 透明度）；`--panel-shadow` = 1px 环 + sm；`--panel-shadow-hover`；`--shadow-popover`；`--shadow-composer`、`-hover`、`-focus`。
**只有可点击的卡片**（团队页卡片、附件）在 hover 时上浮 -1.5px，阴影换成 `--panel-shadow-hover`；对话里的对象一律不上浮。
内部分隔用 `--hairline`：1px，≥2dppx 时 0.5px，≥3dppx 时 1/3px。

**圆角阶梯**（同心：内圆角 = 外圆角 − 内边距）：`--r-xs` 2 · `--r-kbd` 4 · `--r-sm` 6（XS 按钮、菜单行、小 chip）· `--r-btn` 8（按钮、输入）· `--r-md` 10（卡片、面板）· `--r-code` 12（代码、工具输出、LG 按钮、抽屉）· `--r-lg` 16（弹窗、设置卡）· `--r-bubble` 18 · `--r-composer` 20 · `--r-pill` 999。

**字体细节**：
- 工具名和按钮文字用 500，元信息用常规字重的 faint。
- Mono 只用于代码、命令、路径和 id；时间、计数、耗时、token 数、行号改用 Sans 加 `tabular-nums`。
- 标题用 `text-wrap: balance`，段落和列表用 `pretty`，长 id 和路径用 `overflow-wrap: anywhere`。
- 行内图标 `vertical-align: -0.125em`（11–12px 文字用 -0.075em，见 `.vh-icon-inline`）。
- 移动端输入框不小于 16px。
- 暗色字重补偿不采用：IBM Plex 是静态字重，460 会吸附到 500。
- 截断：侧栏标题 1 行，描述 3 行（`.vh-clamp-*`）。

**动效**：`--dur-micro` 60 · `--dur-snap` 120 · `--dur-base` 200 · `--dur-sheet` 300 · `--dur-slow` 450；`--ease-out` / `--ease-snap` / `--ease-overshoot`（overshoot 只用于极小的入场，不用于对话布局）。
`--motion-fast/med/slow` 映射到 snap、base、sheet 加 ease-out。按钮按下 `scale(.98)`，ghost hover 填充过渡 150ms。减少动效时所有时长归零。

**控件**：
- 按钮：XS 24/6/12，SM 28/8/12，MD 32/8/13.5，LG 40/12/15。变体有 primary（ink/canvas）、secondary（soft fill，无环；我们统一不画环，因为次级按钮几乎都在闭合物里）、ghost、danger（只有填充）。
- 键盘焦点（仅 focus-visible）用 `--focus-ring`：1px 画布间隔 + 1.5px accent。**不加 CDS 的 glow**，零偏移彩色光晕仍在禁用之列。对话里的 disclosure 仍用安静的底边焦点轨（B-209）。
- **文本输入框不画焦点环（B-699）**：浏览器把鼠标点击、触屏点按的输入框也算作 `:focus-visible`，所以 `input`（文本类）、`textarea`、`contenteditable` 一律不显示 outline / `--focus-ring` / 外发光，聚焦只靠光标加一处安静的 token 变化（边框 `--line-heavy`/`--text-faint`，或背景 `--fill-hover`/`--bg-3`）。按钮、链接、summary、select 这类控件仍只在键盘 `:focus-visible` 时显示 `--focus-ring`，鼠标点击不显示。全局规则在 `styles/base.css`，组件不要再给输入框加环。
- **hover 一律加守卫（B-728，UI-M-01）**：触屏浏览器会把最后一次点按留作 hover 点，没守卫的 `:hover` 会粘在刚点过的控件上。所有 `:hover` 规则写在 `@media (hover: hover) and (pointer: fine) { … }` 里，原地包裹，不挪到文件末尾（同优先级按源码顺序生效）。`:hover, :focus-visible`、`:hover, .is-selected`、`:hover, [data-state=open]` 这类合并写法要拆开，非 hover 的一半留在原处；`:focus-visible` 那一半不能写 `box-shadow: none`，否则键盘焦点环一起没了。触屏的按下反馈用 `:active`；只在 hover 时显示的控件，触屏下默认可见（如终端标题的改名铅笔）。lint 规则 `hover-unguarded` 拦新增，存量迁移脚本 `scripts/dev/codemod-hover-guard.mjs`（幂等，冲突后可重跑）。
- 分段控件统一用 `.vh-segmented`：999 圆角轨道、2px 内边距、轨道是 alpha 填充、thumb 是表面色加微投影、120ms snap；宽度 ≤254px 时，带图标的非激活项隐藏文字。用于侧栏「列表 / 状态 / 归档」和 Codex 线程切换。
- live 指示：呼吸 2.4s、脉冲 1.2s、流式光标 2px × 1.15em。三点波浪和 shimmer 暂不采用，因为现有 Spinner 和 18px 轨迹已经承担这个角色。

## 3. 字体

- 标题：`IBM Plex Sans`，600–650，字号层级比至少 1.25，字间距 `-0.01em` 至 `-0.03em`。
- 正文：`IBM Plex Sans`，400，App 14–16px，行高 1.45–1.55；长文可到 1.7。
- 机器层：`IBM Plex Mono`，仅用于 session id、机器名、命令、路径、代码、时间戳、版本和度量值。
- 移动端可编辑控件使用 16px，避免 iOS 聚焦缩放；xterm 的专属几何与 16px 隐藏输入底线保持独立。
- 对话区字号只用下方「对话字号档位（B-582）」的 token，全部随「对话字号」设置等比缩放；本节与紧凑工作台标准里的 px 值均指默认档。
- 对话正文遵循下方紧凑工作台标准：桌面 14px / 1.6、触屏 15px / 1.6，顶层段落间隔 12px、列表项间隔 4px；标题前增加分组留白。命令内容复用 Shiki 双主题高亮，输出保持原文。输入区与对话共用背景，不使用顶部横线或外层卡片；输入框用相邻底色与轻微焦点边界区分，队列不另套卡片。输入框正文独占一行，工具和发送位于底部工具栏。＋、权限、模型/强度与单一主按钮始终在同一工具栏水平对齐；窄屏收起权限文字、最窄屏思考档在模型弹层查看，上下文已用百分比与已用/总容量 tokens 直接置于输入框下方，附件和预设放入＋菜单；排队消息贴合输入框上沿，调整方向与删除可直接操作。历史消息原位编辑，主按钮明确“在新分支中发送”，工具之间的中间回复不显示复制/引用。

## 4. 语调

- 控件使用短动词，直接说明动作，不写“欢迎使用”式空话。
- 状态和错误同时说明发生了什么，以及如何恢复。
- 中文使用全角标点；英文标题使用 sentence case。
- 版本、命令和机器信息保持具体，不使用“下一代、革命性、无缝”等营销套话。
- 手机主要动作至少 44px 高；需要连续操作的主按钮优先 48px。

## 5. 禁用范围

1. 不用绿色填充普通主 CTA、发送按钮或确认按钮。
2. 不用装饰性的紫蓝渐变、渐变文字、零偏移彩色光晕或大面积霓虹；最大思考档轨道遵循上面的明确例外。
3. 不用嵌套圆角卡片堆层级；优先表面台阶、间距和 1px 分隔线。
4. 不用超过 1px 的彩色装饰竖条；状态导轨必须有明确语义。
5. 不用多个无语义彩色强调色互相竞争。
6. 不用 mono 装饰普通标题或按钮。
7. 不用模糊/玻璃效果装饰普通 App 面板。
8. 不改变终端 pane 的 always-dark 规则。
9. **不把「第二段对话」原地展开进主对话流**：子代理卡（B-317）、诊断输出这类
   自成一段的内容，展开后是几十行写给机器看的文字夹在用户自己的两段话之间，
   读起来像 UI 坏了。对话流里只留**一行指针**（是谁 / 在做什么 / 多久），
   正文进 session aside 抽屉（`.sd-files` 那一格，窄屏自动变整屏 + scrim）。
   判据是「这段内容有没有自己的时间线」——有就该有自己的容器。

## 6. 交互反馈、组件选择与文案（B-581）

本节补交互层通用规则，借鉴 Orca STYLEGUIDE 的 UX rules；与本文件已有的具体条目冲突时，以已有条目为准，并在下文注明。

### 反馈时机

先按动作的感知时长选反馈，而不是先问「控件要不要变」：

| 时长 | 反馈 |
|---|---|
| 0–100ms | 不给可见反馈，闪一下反而像故障 |
| 100ms–1s | 只禁用 |
| 1–3s | 禁用，加 Spinner 或替换文案 |
| 3s 以上或多步骤 | 阶段文字（真实阶段，不用假百分比） |

- 禁用要立刻生效，防止重复提交；可见的 loading 延迟约 200ms 再出。本地很快、经 relay 会多出 50–200ms 延迟，延迟出现能让快的路径什么都不显示，慢的路径照样有反馈。
- 和 B-513 / B-722 的关系：发送确认态是这条规则的具体实例，以 B-513 为准。气泡降透明度相当于立即禁用；时间位首帧就放一个静态时钟（静态图标不会「闪」，0–100ms 规则针对的是动画/布局变化），超过 150ms 换 Spinner，因为都在时间位、不改变布局，可以比默认更早出现；服务端确认后对勾 1.6s 渐隐，不留永久标记。离线/重连中写明去向（「连接恢复后发送」「会话恢复后送达」），修改类操作就地显示「保存中… → 已保存」。其他异步动作默认延迟 200ms。
- 控件预先占好最终尺寸：要换成更长的文案或多出图标时，一开始就用固定 `width`（不用 `min-width`），执行中途不能变宽。`Button` 的 `loading` 已在组件内统一收口（B-590）：立即禁用，Spinner 延迟 200ms（`ui/useDelayedFlag.ts`），有 `leftIcon` 时与图标共用同一格，没有时叠在透明文案上，`rightIcon` 保留占位，宽度全程不变；调用方直接传 `loading` 即可，不要再自己拼 Spinner。
- 异步状态显示在原操作位置（同 B-436）；减少动态效果时 Spinner 静止，但仍要能看出「进行中」。

### 自己弹出的浮层轮流出现（B-697 / B-830 / B-831）

Radix 模态层（Dialog、默认的 DropdownMenu / ContextMenu）打开时会做三件事：给 `body` 加 `pointer-events: none`、锁定焦点、把其余节点标成 `aria-hidden`。原生 `showModal()` 会进入 top layer，并把其余部分设为 inert。所以两个模态同时出现时，画在上面的那个可能点不到，z-index 解决不了。

- **规则**：凡是自己弹出、或会挡住整页的浮层，都要通过 `app/overlayQueue.ts` 的 `useOverlayTurn` 排队，同一时间只渲染持有者。
  - 优先级：`critical`（登录失效 / 确认弹窗 `AuthExpiredNotice`）> `interaction`（用户要求打开或必须回答的：`?task=` 深链的 `TeamDialog`、`Modal.alert/confirm/prompt`、⌘K 命令面板、会话搜索、⌘P 快速打开、`open_preview` 推送的预览浮层）> `notice`（应用主动弹的，如更新日志）。
  - 高优先级出现时，低优先级的直接关闭，不记为已读或已关闭；高优先级消失后再回来。`critical` 的消失指刷新或重新登录。
  - 同优先级后到的先显示（B-831）：从 `TeamDialog` 里弹出的 `Modal.confirm` 叠在上面，`TeamDialog` 暂时收起，回答后再回来。先到先得会让这个 confirm 藏在等它的对话框后面。
- **非独占的卡片**（安装卡片、通知卡片、登录方式提示，都属 `notice` 级）：只要有高于 `notice` 的浮层持有队列就隐藏让位，不算 dismiss（`useOverlayHeldAbove(OVERLAY_PRIORITY.notice)`）。
- **`Modal.*` 不持有队列时**（被 `critical` 或更新的 `interaction` 压住）：隐藏，promise 保持挂起，也不抢 Esc / Enter。
- **`AuthExpiredNotice` 的实现**：用原生 modal `<dialog>`，portal 到 `<body>`，加 `pointer-events: auto`。用户自己打开的菜单或对话框不在队列里，会留在下面并变成 inert，不会抢点击。
- **新增浮层**：选一个优先级接入队列，不要靠更高的 z-index 盖过别人。回归用 `e2e/auth-dialog-priority.mjs` 跑 desktop + phone（N/M/R：登录失效；A/B/C：更新日志 + `Modal.*` / 命令面板）。
- **仍不在队列里的**：用户点开的 Radix 菜单 / 对话框和行内 `.ns-backdrop` 对话框（更新日志锁页时点不到它们，登录失效弹窗在 top layer 上盖过它们）；横幅、Toast、功能提示等不挡页面的提示。

### 选择控件（B-714）

产品界面不用原生 `<select>` / `<option>` / `<datalist>` / `input[type=checkbox]` / `<summary>` 三角：系统下拉在 iOS、Android、桌面各是一套，不能搜索、分组、写禁用原因，也不跟主题。design lint `native-control` 拦新增，白名单只有 `ui/Checkbox.tsx`、`ui/Summary.tsx` 自身。

- **触发器** `.vh-select-trigger`：桌面 32px（`size="md"` 表单 36px），coarse 44px；`--bg-2` 底 + `--line` 边框，闭合容器里用 `variant="soft"`（填充、无边框），筛选条用 `variant="chip"`；Sans 13.5px，手机 16px；选中值单行截断，完整值在 `title`；`busy` 用 Spinner 替换 chevron，宽度不变。
- **浮层**：`--surface-popover` + `--shadow-popover`，`--r-md`；最小等于触发器宽，最大 min(420px, 100vw−24px)；行高 32px（coarse 44px），高亮 `--fill-selected`；左侧 16px 勾选列，可带说明行（12px faint）和右侧元信息。
- **手机**：`(pointer: coarse) and (max-width: 600px)` 下改为底部 sheet：标题即字段名，搜索固定顶部，行高 48px，留 safe-area；点 scrim、Esc、下滑标题区关闭。系统返回键不处理：data router 在 popstate 上会重跑导航，和 `MessageReader` 等现有 sheet 一致。
- **键盘与读屏**：触发器是 select-only combobox（`aria-haspopup=listbox`、`aria-expanded`、`aria-controls`）；无搜索时焦点留在触发器，用 `aria-activedescendant` 指向高亮项；有搜索时焦点进搜索框（`role=combobox`）。↑↓ / Home / End / PageUp / PageDown 移动并跳过禁用项，无搜索时首字母 typeahead，Enter / Space 选中并关闭，Esc 关闭回触发器，Tab 关闭并去下一个字段。
- **表单**：`name` 渲染隐藏 input，`FormData` 可直接取值；`required` 未选时提交被拦，触发器下方用 `.tg-error` 写原因，不弹浏览器气泡。
- **代码位置**：`ui/SelectMenu.tsx`、`ui/Combobox.tsx`（文案取 `t('picker.*')`）共用 `ui/picker/Picker.tsx`；公开页不能引入 app 的 i18n，直接用 `Picker` 并传 `text`。

### 文案

- 不夸大：代码手里没有对应的结果数据时，不用「已跳过 / 已验证 / 已修复 / 已删除 / 已发现」这类结果动词。等待期间用中性的过程描述（「检查中」「正在提交」），拿到真实结果再换成结果动词。
- 去掉填充词：不写「请」「只需」「简单地」「您可以」，也不用没有状态支撑的泛泛成功语。这条补充 §4：§4 规定短动词，这里规定要删掉的词。
- 取消、关闭、放弃、忽略不是破坏性操作，只是退出当前动作：保持安静，不上色、不加快捷键角标、不加动画提示，视觉重量留给确认动作。实现上用 `.vh-modal-btn.is-cancel`，Esc 仍然可用。`--danger` 和 `destructive` 只留给会丢数据或无法撤销的动作，这类确认不响应 Enter（见 `ModalProvider`）。

### 相邻组件一致

相邻组件指同一领域、行为有重叠、在同一流程里前后出现的组件，比如消息操作栏和排队 dock，或者下拉菜单和右键菜单。它们要读起来像同一个设计：图标、快捷键约定、提交和取消语义都一致，用户在两者之间切换时看不出接缝。要和相邻组件不同，必须有理由：要么相邻组件本身错了，就两边一起改；要么新组件的角色确实不同，就明确定下来。没有相邻组件时，对齐周围界面的按钮尺寸、图标粗细和语气；不要从用户根本不会联系起来的页面硬找「相邻组件」。

### 触屏行内操作、命中区与边缘手势（B-798 U1–U3，B-800 U4）

- **U1 长按只是快捷方式。** 任何 `ActionContextMenu`（长按 / 右键）在同一行都要有常驻可见的 ⋯（`ActionDropdownMenu`，同一份 `items`），触屏 44×44；行上最高频的动作（如侧栏组头的新建 ＋）触屏常驻。写法是**默认可见，只在 `@media (hover: hover) and (pointer: fine)` 里隐藏、hover 时再显示**（`.sb-workspace-new`、`.sb-tree-acts`、/projects 行），不要反过来「默认隐藏、hover 显示」。暂不做左滑行动作（Web 手势与系统边缘返回、横向滚动冲突）。确有别的触屏入口时（如 diff 行点按开评论），在隐藏规则上写 `design-lint-allow: <理由>`，或在 `ActionContextMenu` 上方三行内写 `touch-parity-allow: <理由>`。
- **U2 菜单形态统一。** 所有 ⋯ 菜单限高可滚；手机窄屏上点 ⋯ 与长按是同一个带标题的底部 sheet（`sheetTitle`，B-798 PR B）。
- **U3 命中区 44px。** 触屏下可点控件不小于 44×44；视觉要小时用绝对定位的 `::after` 负 inset 扩热区，视觉尺寸不变。句中的行内文字链接按 WCAG 2.5.8 例外。
- **U4 边缘手势（B-800，`src/app/edgeGesture.ts`）。** 抽屉档从左边缘（rail）右滑拉开抽屉、在抽屉/遮罩上左滑收起，抽屉跟手，松手按距离（40%）或速度（flick）决定。返回手势只在 standalone PWA 接管（iOS 主屏应用没有系统返回）：会话页、二级页左边缘右滑 = `appBack`，箭头跟手、到阈值变实心；浏览器标签页里不接管，交给 Safari / Chrome 自己的边缘返回，抽屉档在浏览器里也把最外 16px（物理）让给系统。所有判定从 `--sa-l` 之后量；起点在可横向滚动的元素（代码块、表格、终端按键条、面包屑、标签条，或 `[data-no-edge-swipe]`）里一律不触发；纵向笔画锁轴后放弃。`prefers-reduced-motion` 下松手直接到位（跟手位移本身是直接操作，保留）。回归：`node scripts/dev/device-shots.mjs --gestures`。
- 防回归：lint `hover-reveal-needs-touch`、`touch-target`（见下节）；`src/ui/touchParity.test.ts` 要求每个 `ActionContextMenu` 在同文件有同一 `items` 的 `ActionDropdownMenu`；`device-shots` 在粗指针预设下把 `smallTargets`（< 44px）和 `hiddenActions`（有 aria-label 却 0×0、所在行在屏上）作为门禁。三处存量名单（`REVEAL_ALLOWLIST`、`TOUCH_PARITY_ALLOWLIST`、`scripts/dev/touchGate.mjs`）只减不增，每条写归属，修好就删（前两份的过期条目会让测试失败）。

### 改动行 lint

`node scripts/dev/check-design-lint.mjs [--base <ref>]`（CI 的 Quality Gates 以 PR base 为基准运行）只检查 `packages/happy-web-v2/src` 下 .css/.tsx 的**新增行**，存量问题不要求迁移：

1. 裸色值：`#hex`、`rgb()`/`hsl()` 字面量。参数里带 `var()` 的写法放行，比如 `color-mix(… var(--x) …)`；阴影和遮罩用 `--shadow-*` / `--scrim`。豁免 `tokens.css`、测试文件，以及只能写字面量的 xterm 主题（`WebTerminalScreen.tsx`）。
2. 对话区 css（脚本里的 `CONVERSATION_CSS`：对话流、工具和子代理行、实时状态、输入框、侧问、提问步进、阅读辅助）的 `font-size` 与 `font` 简写只能用对话档位 `var(--chat-fs-*)` / `var(--conversation-size)`；写死 px、`var(--fs-*)`、未乘 `--chat-scale` 的 `--workspace-primary-size` 都报。触屏输入的 `max(16px, var(--chat-fs-body))` 和 em 放行。
3. `outline: none|0`：同一文件里没有对应的 `:focus-visible` / `:focus-within` 替代样式就报。`X:focus { outline: none }` 这种程序化聚焦容器的写法放行。
4. 文本输入框焦点环（`field-focus-ring`，B-699）：选择器在 `:focus*` 状态下指向 `input` / `textarea` 或以 `input`、`textarea` 结尾的类名，且声明了 `var(--focus-ring)`、`var(--accent-glow)` 阴影或非 none 的 outline 就报。`:not(...)` 里的排除、checkbox/radio 等非文本 input 放行。
5. 原生控件（`native-control`，B-714）：tsx 新增 `<select`、`<option`、`<datalist`、`type="checkbox"`、`<summary` 就报，改用 `SelectMenu` / `Combobox` / `Segmented` / `SuggestInput` / `Checkbox` / `Summary`（见 §6「选择控件」）。只有 `ui/Checkbox.tsx`、`ui/Summary.tsx` 可以写对应的原生元素；字符串字面量里的同名文本放行。

6. 未守卫的 hover（`hover-unguarded`，B-728）：`:hover` 规则不在 `@media (hover: hover)` 里，或写在 `(pointer: coarse)` / `(hover: none)` 里就报；`:not(:hover)` 放行。这条另有全仓模式 `node scripts/dev/check-design-lint.mjs --all-hover`，CI 的脚本测试要求存量为 0。
7. 触屏看不到的 hover 显示（`hover-reveal-needs-touch`，B-798 U1）：控件在 hover 守卫外被 `display:none` / `opacity:0` / `visibility:hidden`，只靠守卫里的 `:hover` / `:focus-within` 同一属性显示，且没有 `(pointer: coarse)` / `(hover: none)` 规则让它可见就报；隐藏行或显示行任一是新增行即报。全仓模式 `--all-reveal`，CI 的脚本测试要求存量只来自 `REVEAL_ALLOWLIST`。
8. 触屏命中区（`touch-target`，B-798 U3）：`(pointer: coarse)` 块里给交互类（类名以 btn、button、act、action、toggle、close、chevron、menu、item、tab、chip、back、trigger、switch、link、more、new、add 结尾）写 16–43px 的 height / min-height / width / min-width 就报；同文件给该类写了 `::before` / `::after` 的视为已扩热区。

确实要保留时，在同一行或上一行写 `design-lint-allow: <理由>`，理由必填。规则本身宁可漏报、不要误报，误报应该修脚本，不要靠堆豁免。

## 实现检查

- Landing、更新窗、登录和 App 的 primary action 使用同一套 ink/canvas 关系。
- 绿色面积随实时状态数量变化，而不随可点击控件数量变化。
- focus 必须可见；触屏命中区和 16px 输入字号不得因视觉收敛退化。
- 两个主题、390px 手机宽度和桌面宽度都不得出现横向页面滚动。
- 带变换或装饰溢出的交互图，点击并聚焦内部按钮后也须检查外层容器的 `scrollLeft`；
  `document.documentElement.scrollWidth` 没有溢出不能证明页面没有横移。首页由文档负责纵向滚动，
  `.pub-page.pub-landing` 使用 `overflow: clip visible`；`clip auto` 会计算成
  `hidden auto`，使聚焦能够横向滚动装饰内容。此修复仅限首页，不套用到其他滚动容器。
- 新组件优先复用 `vh-*` 与 token；新语义 token 先更新本契约和 `tokens.css`。
- 同优先级（同 specificity）的 CSS 覆盖规则必须写在被覆盖规则之后：层叠按源码顺序取后者，写在前面的覆盖静默不生效（B-653、B-359 都踩过）。新增覆盖时用 computed style 核对它确实赢了，不能只看规则存在。

| 浏览器标签 | `favicon.png`（32 像素版）/ `favicon.ico` | 青绿块 + 黑色 `^_^`，亮暗标签栏都可辨；像素版不做抗锯齿缩放 |
| PWA / iOS 主屏 | 满版青绿 tile，`^_^` 缩到 0.84（maskable 0.72，落在 80% 安全圆内） | 图块本身就是 App 图标，不再方框套方框；iOS 由系统加圆角，`icon-192/512` 自带圆角 |
| 链接预览 / GitHub | `og-image.png`（暗）、`og-image-light.png`（亮）、`.github/social-preview.png` | 字标 + slogan；运营者品牌（`BRAND_ICON_URL`）替换时退回小卡 |
| 大型加载展示 | 既有连接图，中心为静止 mark | 活动动画与 Logo 分开，不旋转/变形 Logo 本体 |

- **最小尺寸**：矢量主标 ≥ 20px；16–19px 用 16 像素版，32px 场景优先 32 像素版。任何尺寸都保留嘴巴，`^ ^` 不单独出现（单独时会被读成两个 Λ）。
- **留白**：四周净空至少图标宽度的 1/4；保持 1:1，不拉伸、不裁切。
- **亮暗**：应用内跟随主题 `--text`（亮色为墨黑块、暗色为浅色块），镂空透出背景，不另垫底色；静态图标只有青绿 tile 一种（亮/暗系统都用它），墨黑 tile（`very-happy-app-icon-ink.svg`）只用于亮色物料。
- **禁止**：不加橙色或暖色调（避免靠近 Claude Code 的橙色像素吉祥物）、不给方块加身体/手脚/像素化轮廓、不改五官（形状、比例、间距、眨眼）、不旋转/倾斜、不加阴影/发光/渐变/描边圈/状态光框；`--accent` 仍只表示 live，不给应用内 mark 上色。
- **动态版**（`very-happy-mark-animated.svg`，3 秒一轮依次「打」出 `^`、`_`、`^`）只用于品牌展示位，`prefers-reduced-motion: reduce` 停在完整帧；工作台内一律静止。B-720 Landing「字符聚拢成方块再镂空」用 `markMask()`，不另画形状。
- 语音助手四态共用静止 mark：待机无光晕，聆听音量环、思考弧线和朗读波形放在独立层；不缩放 Logo、不添加圆形底框或状态光框。手机操作维持 44px，语音执行和麦克风权限不因视觉改版变化。
- 与「Claude Code / Codex / Pi」身份分离：产品 Logo 不代表后端 agent，模型名称也不替代 agent 身份。
- 有文字品牌时图形装饰性 aria-hidden/空 alt；只有图标的交互入口必须提供明确可访问名称。
- 正式启用前的商标检索由 Owner 决定是否进行（B-724 只做了公开网络的简单撞标检查）。

## 右侧工作区标签

文件目录、多个文件预览、改动、快捷笔记、运行概览、浏览器预览，以及会话的预览/剪贴板记录（B-602）使用同一个右侧工作区。
桌面三栏并排，对话拥有独立滚动；不再为每项长期辅助内容弹出独立模态卡片。
默认右栏约 36vw、最少 320px；总宽不足 1100px 时转为全屏面板，关闭回到原对话。
分隔条（B-609）是 `role=separator` 的 pointer 事件手柄：鼠标、笔、触屏均可拖（4px 死区），拖动中 Esc 取消并回到起始宽度，双击恢复默认宽度；拖到不足 200px 时面板变淡，松手即收起（不记住这个宽度，再打开恢复上次宽度）。可聚焦，左右方向键 16px（Shift 64px），Home/End 到最小/最大；焦点只在接缝上显示 accent。

- 单实例工具重复打开激活已有标签；不同文件按路径区分。标签支持选中、关闭、键盘左右/Home/End。
- 切换标签保留草稿、各自滚动位置；当前会话内收起整个面板保留挂载内容，隐藏时不抢焦点或拦截键盘。切换会话/终端身份释放旧视图，关闭具体标签释放该标签，关闭最后一个内容标签时收起面板；跨整页导航仅恢复各功能明确保存的视图信息，不承诺外部网页运行状态。
- 标签过多时横向滚动，不把标签挤成无法点击的图标；手机关闭目标至少 44px。
- 激活标签只调整标签栏自己的横向滚动，不能使用会滚动祖先的 scrollIntoView；嵌入 Landing/文档的工作台展示不得在挂载时抢走整页阅读位置。
- 所有工作区标签仅保留关闭按钮，不展示“更多”图标或移动菜单。鼠标拖拽排序，键盘 Alt+Shift+左右箭头作为等价操作；hover/focus 只改变颜色，不新增图标、不改变宽度或推挤相邻标签。关闭和拖拽落点均不能引发布局跳动。
- 标签必须关联真实 session/workspace 身份。切换会话不得把旧文件冒充新目录；生产迁移时保存/恢复各自工作区。
- 笔记草稿不因关闭标签丢失，真实同步/保存失败沿用现有机制。文件/改动保留路径与只读/可编辑状态。
- 新建、审批、删除确认等短事务仍可使用模态框；不能为了“所有东西都在右侧”隐藏关键审批。
- 浏览器预览是专门能力：需要处理目标地址、远端端口、嵌入策略、加载失败与导航。生产工作区提供用户输入 URL 的沙箱 iframe、刷新和外部打开；不声称任意站点都能嵌入，不自动代理远端 localhost。原型中的浏览器示意仍不访问网址。

## 面板栏与系统状态（第七轮）

- 右侧仅保留一条标签栏；新增标签、收起与标签切换同排，不叠加“工作区”标题栏。
- 机器名、Agent、relay 区域放会话顶栏，正文不额外占一行元信息。窄屏压缩非主要图标与长名称，完整信息保留详情；对话标题必须仍有可读空间。
- 启动状态：使用 Very Happy 静止 mark 作为连接中心，四周为 Agent、终端与工作空间，细连接线轻脉冲。保留多 Agent 汇聚的品牌意象，去掉满屏网格与旋转卡片；不用假百分比。连接图表达产品身份，不代表各服务已连接；真实进度仅由状态文字表达。读取真实主题，避免加载前后闪色。
- 路由加载：保留导航与输入区尺寸，正文显示静态骨架和单行状态；不用全屏品牌动画遮挡已有工作。
- 空状态：说明下一步并提供一个主要动作；不要只写“暂无数据”。
- 加载失败：保留旧内容和草稿，给出重试/返回；不得自动清空会话或承诺未验证的恢复结果。
- 断线恢复：轻量行内提示，保留阅读和草稿；继续沿用唯一 resumeSync 恢复通路，不另造轮询或重连策略。
- 权限等待：请求、操作内容与明确选择保留在对话可见区域，不能隐藏进普通标签；视觉与状态模型分开，审批能力门控保持。
- 减少动态效果时活动条与脉冲静止，所有状态有文字说明；不得依赖动画单独表达状态。

正式接入首屏需同时更新 index.html 预绘制与 RouteLoading，并保留现有移除时机、超时恢复、失败回退与主题来源，不能只替换 React loading。
首屏预绘制与 React 加载共用品牌图形、样式及主题读取；`/dev/workspace-design` → 会话工具 → 界面状态仍用于查看其他状态原型。


### 终端、右键与拖拽（第八轮交互提案）

- 终端 session 在同一会话列表中用终端图标区分，顶栏保留机器、目录、连接状态。终端始终深色；Agent 输入与终端键盘输入是独立模式，不能用普通消息发送假装写入 PTY。
- 会话行右键与省略号共用菜单：重命名、标签、排序、归档等按实际能力展示。终端菜单明确区分关闭视图、断开连接和结束进程；结束进程须明确确认，不能把关闭标签绑定到杀进程。
- 文件与右侧标签可右键：复制路径、打开、关闭当前/其他标签等仅对有效对象可用。菜单跟随点击位置并避开屏幕边缘，Escape/外点关闭、关闭后还原焦点，键盘菜单键可打开；文件行触屏保留可见省略号替代；工作区标签在桌面（精确指针）只保留常驻关闭按钮，不加省略号；触屏上只有当前激活的标签多一个常驻 ⋯（44px），菜单与长按一致，无可用项时不显示（B-798：触屏没有右键，「关闭其他标签」原本只能长按；只给激活标签加，是为了不把标签条挤满）。看板卡片和笔记行同样有常驻 ⋯，与长按共用同一份菜单项；精确指针设备上悬停才显示。
- 终端查找（B-557）：搜索条浮在终端右上、只用 `--term-chrome-*`；命中高亮用琥珀 `--term-search-*`（取自终端调色板黄色），不占用 live accent，也不改写终端选区。
- 不拦截正文、输入框或终端选区的原生右键与长按复制。终端粘贴需走现有权限和剪贴板机制，不能右键即执行命令。
- 拖拽会话只在手动排序有效的视图启用；分组视图不得无意改项目归属。标签拖拽仅改变标签顺序，不复制会话。两者都显示插入落点；会话列表保留菜单移动替代，工作区标签使用 Alt+Shift+左右箭头，不增加移动菜单或操作图标。
- 文件拖入输入框表示添加附件，提交前展示列表和移除入口；拖到预览区表示打开预览。不得因拖入终端自动上传/执行，未支持目标显示不可放置。
- 右栏宽度可用分隔条调整，设置最小正文宽度；手机用全屏面板，不提供难操作的分栏拖柄。持久化、会话隔离、断线/重连/只读/进程结束状态均需在正式迁移时验收。
- 真实会话列表、工作区标签和终端已接入本地实现，功能覆盖与边界见实施台账；设计示例不作为真实运行证据。文件拖放只在已支持的目标生效，不以此标准承诺任意文件跨机器传输或终端执行。

### 手机登录页

登录表单在可用视口内水平、垂直居中；用自动外边距吸收剩余空间，内容超过屏幕时从安全区顶部开始滚动，不得裁切顶部。软键盘展开时沿用 visualViewport 固定高度，解除 min-height 限制并取消垂直自动外边距。手机登录去掉外层阴影/玻璃卡片，保留品牌 mark、语言、所有登录方式与帮助法律入口；输入字号 16px、主要操作至少 44px。

注册页遵循相同的手机表面和居中规则，邀请码、关闭注册与容量提示仍可达。触屏初次打开登录/注册不主动聚焦输入，用户请求验证码后的聚焦继续保留；品牌 Logo 在注册、配对和空状态中同样不加发光。

保持醒目的排版、Very Happy 反白 ^_^ 块、机器/Agent 汇聚与有节奏的动效；主题、字族、按钮与基础材质保持统一。允许有语义的连接图与局部背景纹理，不以整页廉价光晕替代设计。

### ASCII 景深背景（B-720）

共用引擎 `src/ui/asciiField/`（`AsciiField` 组件 + 懒加载引擎），取代 B-700 只在空状态的单条海浪。三层字符场：远景小字号、低不透明度、模糊（模糊烘焙进字形图集，不做每帧 CSS blur）；中景；近景清晰、更亮、漂得更快。字符只用 ASCII 密度梯度，墨色取 `--text`（亮色主题 `--ascii-gain` 补偿），生物（鱼、鲨鱼、水母、微笑终端标）同为墨色——`--accent` 仍只表示 live。

强度从强到弱：Landing hero（全幅，鼠标/滚动视差，文案列下垫 `--bg-0` 晕染保 AA）> App 默认页（全区域，标题与按钮下同样垫晕染）> Landing 分隔带与结尾 CTA、文档页头带 > 会话页（B-752 `chat` preset：只有远景+中景、无近景无生物，墨色约为默认页的 40%；固定在对话流背后不随滚动。820px 消息列两侧各有 ≥120px 空白时只在两侧各放一条字段，列背后不放，内侧与底部用 `--bg-0` 渐变淡出；没有两侧空白（手机、窄窗）时铺一整块，强度减半（`--ascii-gain`）。不用 CSS mask：mask 每帧多一次离屏合成，动画层也会让整块区域每帧重绘）> 设置页头带（很淡）> 侧栏底部（极淡，只在 footer 与列表尾部）。新增位置先选现有 preset，不另调一套参数；文字对比度以像素取样验证（背景最亮像素对文字色 ≥ 4.5，大字 ≥ 3）。

运行约束：≤30fps；标签页隐藏或元素离屏（IntersectionObserver）暂停；`prefers-reduced-motion` 只画一帧；手机 / coarse 指针 / ≤4 核或 ≤4GB 降为两层、无模糊、无鼠标视差。每帧主线程只写 transform，层内容按页面共享的 1ms 预算分行重绘后交叉淡入。「设置 → 外观 → 背景动效」为设备级开关（localStorage `vh-ascii-motion`，不进 synced settings），关闭后不挂载、不加载引擎。会话页额外按负载降速（`setPace` / `backdropPace`）：平时 15fps；手机 / 低端（lite 档）只画一帧静止画面、不跑循环（preset `liteStill`），对话区内任何滚动（含自动跟随）期间暂停、停 500ms 后恢复，agent 工作中 ≤8fps；终端视图不挂。

### 新手引导与操作反馈（B-436）

首次使用优先连接机器；常驻帮助把连接入口放主操作，并说明执行电脑、relay、手机与 Agent 的分工。官方 skills 按团队、内置待办、外部 provider 区分，不暗示安装即授权或接管。运行列表用右侧紧凑 Spinner，等待/未读保留各自语义；减少动态效果时静止。新建与发送的异步状态必须在原操作位置可见，不加假延时或百分比。折叠屏除了页面视口，还参考实际屏幕宽度；布局与浮层采用同一条件，切换不得重建当前表单。

### 团队启动（B-438）

创建以目标输入为中心，复用最近电脑/项目并在配置摘要中明确显示，未知配置展开选择；高级选项可修改，不把选择表单铺满首屏。启动等待沿用发送处 Spinner，成功进入负责人的真实对话。无 session 的成员仍显示名称和“准备中/需处理”并链接任务详情；启动错误在任务详情就近显示，不藏在整页底部。

### 目录内新建（B-446）

工作目录分组标题旁常驻新建加号，与查看改动按钮同排，hover 不改变宽度；触屏命中区 44px。
快速新建优先使用显式目录，其次当前路由会话/终端的机器与原始目录，无上下文才使用最近记录。
目标离线或目录未知时打开配置并保留预填，不静默换机器；始终询问配置的设置仍生效。

### 文件预览操作（B-447）

会话文件入口使用文件夹图标，默认目录浏览。弹窗与右侧文件页共用预览和操作：下载原始文件、复制路径、复制完整文本；未加载完整文本时不把片段标成完整复制。弹窗可固定到当前同机器工作区，路径保持从左到右，不改真实路径字符。
表格采用本地只读网格、工作表切换和分页，不外传文件；边界与格式限制见 [文件预览 spec](../specs/2026-09-file-preview-actions.md)。窄面板路径与操作分两行，图标始终占位，触屏操作至少 44px。

### 右侧工作区画布与接缝（B-448）

对话、右侧工作区和右侧拖拽命中区共用 `--bg-0`，分隔仅用一条 1px `--line`；不能用亮色拖拽带或卡片底色割裂正文。文件树、预览和工具条继承宿主表面，弹窗保留自身 `--bg-1`；左侧导航保持相邻面板层次。标签选中用 `--bg-2`，不因统一画布失去选中反馈。

文件代码预览与路径栏共用宿主画布：取消代码高亮自身底色和外层重复留白，只保留代码内部阅读间距。此规则仅用于独立文件预览，不改变聊天代码卡片及其折叠渐隐。

### 右侧工作区收敛（B-451）

工具从标签栏的＋菜单打开；已打开文件、笔记、侧问和浏览器继续使用统一标签，选中态为中性圆角底色，不再逐个画竖线。关闭按钮始终占位，拖拽与键盘排序保留。笔记正文使用对话字号和行高 token，移动端编辑仍为 16px。侧问不重复顶部说明行，边界说明放空状态和输入工具行。

面板切换只允许 140ms 轻量淡入，不位移、不缩放、不动画布局；减少动态效果时禁用。正文运行状态是纯展示，hover 保持透明且不变色，不设置展开箭头或可点击样式。

### 统一 Agent 状态（B-452）

侧栏左侧只表达会话类型：UI 对话与 Claude/Codex/Pi 终端均用中性灰符号，名称进入可访问标签。右侧固定一个 16px 状态位，依次呈现等待操作（warn）、运行转圈、未读红点、离线/状态未知；空闲留空。移除状态点光晕和左侧彩色副点。未知不等于空闲，未读独立保存。侧栏与状态列表共用新鲜度判定，终端观察不依赖单纯有输出或进程存活。

侧栏品牌栏和对话 header 不再显示独立连接圆点；对话连接信息由中继 tag 承载，避免与会话行的 Agent 状态重复争夺注意力。

正文活动状态采用紧凑行：活动名称、分隔点、耗时及实际 token 数相邻排列，不再展开；hover 不改变画布底色。同一轮内连续完成的 Terminal 命令折叠为带数量和最后一条命令摘要的组，展开仍保留各条命令及输出；不跨正文、其他工具、运行中或失败命令分组。

子代理：正文保留与工具对齐的入口，详情留在右侧。运行中的子代理在输入框上方显示横向紧凑任务条，完成/停止即移出任务条，历史入口保留；任务说明默认展开、可手动收起，右侧过程复用正常消息与可展开工具组件，不再只显示原始日志列表。

主对话与子代理的执行过程共用 ActivityMessages；仅合并相邻已完成终端调用，运行、出错及中间文字保留独立行。工具组不画左侧装饰竖线，以间距、展开箭头和状态图标表达层级。

子代理任务名称和主要运行状态与正文共用 `--conversation-size`（桌面 14px、触屏 15px）；不把“运行中”缩成 11px 徽标。层级通过字色和留白区分，工具次数、耗时等辅助度量可保留小字号。

子代理字号补充：任务说明、运行摘要、模型名称、章节标签与主对话正文统一字号和 1.6 行高；普通状态摘要使用 Sans，不用 11px Mono 模拟日志。任务说明复用正文段落及列表间距，仅工具次数/耗时等度量保留辅助字号。运行控制弹窗固定标题与关闭按钮，内部内容独立滚动；首次打开焦点放标题，不能自动滚到首个操作。

工具行统一：工具名、路径、合并命令组、预览历史与正文共用 conversation-size/leading。普通标签使用 Sans，路径和命令保留 Mono。完成的 open_preview 直接显示“文件预览＋可点击路径”，失败/运行仍保留原始工具详情。子代理正文入口去掉重复 Task 标签与原始命令摘要，用共用18px首图标槽（状态图形保留原尺寸）、任务名、状态/次数和单一打开箭头；桌面单行，手机状态在任务名下方，点击目标至少44px。运行入口复用 Spinner，减少动态效果时静止，完整过程仍在右侧查看。

### 预览与剪贴板记录（B-602）

输入框上方只放计数 chip（「预览 N」「剪贴板 N」，外形同子代理任务条，无记录不渲染），不在输入框上方展开列表。点 chip 打开右侧工作区对应标签（`?panel=previews` / `clipboard`），再点收起；＋菜单同样可开。每类一个标签，不在面板内再叠一条子标签栏。列表行与终端页的内联记录共用 `ToolHistoryEntries`，打开/下载、再次复制与长文本展开保持一致。

### 消息操作与时间（B-454 / B-456）

用户消息和回答底部的消息操作栏常驻，桌面与手机一致；复制、引用、编辑仅保留图标，各自提供用途提示和可访问名称，手机点击目标至少 44px。原位编辑及其取消/提交按钮保留明确文案。操作栏旁直接显示真实创建时间 `HH:mm`，悬停这枚时间显示本地完整日期、时分秒及时区；仅附件和本地命令消息保留时间，不提供空内容操作。

工具之间的中间回复仍不新增操作栏。正文、思考、事件、team/peer 卡片等消息行（`.msg`）整行不再有时间悬停（B-514，Owner：「消息正文鼠标 hover 会展示时间，这个逻辑去掉」），完整时间只在底部 `HH:mm` 上悬停可见；工具行（单条、合并组头、文件预览、子代理说明）没有可见时间，保留完整时间悬停提示。合并工具组显示真实时间范围，展开后各条显示自身时间；主对话与子代理复用同一格式。无有效时间时省略，不从父消息或当前时刻推测。路径、按钮的操作提示保持优先。

### 发送确认态（B-513）

用户消息在服务端确认落库前为「发送中」：气泡立即降透明度，持续超过 150ms 才在时间位出现 Spinner，隐藏引用/编辑、保留复制。15s 未确认或服务端明确拒绝即「发送失败」：以 `--danger` 文案「发送失败 · 重试」替换底部时间；仅在确定服务端未落库时追加「放回输入框」（只放回文本，带附件的回合只给重试）。排队 dock 行同样显示两种状态，优先级 failed > sending > queued。

### 离线提示（B-799）

- 判定唯一来源 `sync/networkStatus.ts`：`navigator.onLine === false` 持续 1.5s，或曾连上的 socket 在**可见时间**里断开满 8s（socket.io 1s→5s 重连 + 5s 探活之外）。隐藏期间不计时，回前台从 0 起算；首次连接前只认浏览器离线。恢复需浏览器在线且 socket 回来。只是显示/发送状态，不做重连（恢复仍走 AGENTS 13 的 resumeSync）。
- 顶部细条 `app/NetworkBanner.tsx`：「已离线，正在重连…」用 warn，「已恢复」用 accent（connected 语义），2s 后 200ms 淡出。细条自占一行：底色铺到顶部 inset 下，文字落在 inset 之下并避开左右 inset；显示期间 `.app-shell` 和抽屉下移 `--net-bar-h`（24px），不盖住页头按钮。`device-shots --pages offline` 断言没有壳内按钮落在细条下。
- 离线发送：纯文本照常发，按钮换 CloudOff、标签「离线排队 · 联网后自动发送」，输入框占位同义；它进 outbox / 服务端队列行，离线期间 15s 截止计时暂停（含 onLine 仍为 true 的断网），恢复时立即重发。带附件的发送离线时禁用并写明「附件需要联网上传」（上传先于消息，离线会被退回，见 B-734）。

### 对话行左边界（B-455）

正文列负责与输入框对齐；工具组、单工具、预览、子代理入口与 loading 不再各自添加横向内边距。首图标占位统一用 `--conversation-icon-size`（18px），与正文共用起点；工具组、预览、子代理及 loading 的首文字位于该起点后 26px（18px 图标＋8px 间距）。单工具保留独立状态标记，不为了补齐它的双图标而增加其他行缩进。主链路与子代理的思考块统一无左侧竖线或缩进；代码框与工具展开内容保留其内部阅读留白。纵向触屏命中高度保持至少 44px。

### 对话字号档位（B-582）

对话区只用 6 个字号 token，全部是 `calc(默认px × var(--chat-scale))`；`--chat-scale` 由「外观 → 对话字号」决定（小 0.9 / 默认 1 / 大 1.125 / 特大 1.25，本设备保存，`html[data-chat-size]`）。默认档与 B-582 之前逐像素一致。

| token | 默认 | 用于 |
|---|---|---|
| `--chat-fs-body`（= `--conversation-size`） | 14 / 触屏 15 | 消息正文、工具/子代理行、卡片正文、输入正文 |
| `--chat-fs-control` | 13 | 卡片标题、权限说明、对话内按钮文字、命令头 |
| `--chat-fs-secondary` | 12 | 标签、时间、计数、行下第二行 |
| `--chat-fs-code` | 12 | 代码块、命令输出、工具结果 |
| `--chat-fs-caption` | 11 | 度量、注脚、mono 小标题 |
| `--chat-fs-badge` | 10 | 徽章、附件文件名 |

- 间距单位 `--chat-space`（默认 4px）随档位缩放：对话区 gap/padding/margin 写 `calc(var(--chat-space) * N)`，行高度（工具行 7.5–8、子代理入口 9、实时状态 8）同样用倍数。首图标槽 `--conversation-icon-size` = 18·s，B-455 的首文字起点因此是 26·s。
- 对话内 lucide 图标由 `.cl-inner` / `.sap-body` 的 `svg.lucide { zoom: var(--chat-scale) }` 统一缩放；直接给 svg 设宽度的规则要写 `calc(var(--conversation-icon-size) / var(--chat-scale))` 抵消 zoom。
- 命中区只增不减：触屏一律 `max(44px, …)`。手机输入 `max(16px, var(--chat-fs-body))`。
- 不缩放：终端 pane（铁律 9）、对话列宽 820px 与左右内边距（含输入框上方 dock 的水平内边距）、输入框工具栏控件、diff 视图、侧栏/顶栏/弹窗/菜单。
- **浮层与弹窗一律不缩放**：浮在对话上的 chrome（选中引用、提问导航轨预览、悬浮时间）、弹窗/预览（运行控制、图片预览、skill 文档预览、卡片消息阅读器 `.msg-reader`）和终端页的工具历史列在 tokens.css 的「固定比例岛」里，岛内 `--chat-scale` 恒为 1，档位 token 按默认值计算。新浮层若复用对话 css，要加入这份名单。弹窗正文需要对话正文字号时用不乘比例的 `--conversation-size-base`。设置作用于所有复用这些 token 的阅读面（对话、侧问、子代理面板、笔记，以及文件/skill 预览和团队详情里的 Markdown/代码块）。
- 不做双指捏合调字号（会和页面缩放、长按选择冲突），理由见 [spec](../specs/2026-10-chat-type-scale.md)。

### 图片与 skill 预览（B-457）

输入框已选图片与历史附件共用站内图片预览：点击缩略图打开，默认完整适应画布，提供缩放、原始尺寸、下载和关闭；放大只在预览画布内平移。B-608：触控板捏合与 Ctrl/Cmd+滚轮以指针为锚点缩放；普通滚轮/双指滑动在图片大于画布时平移（Shift 横向），图片完整适应时才缩放（手势上限 8×，按钮仍是 ×1.25、上限 4×），拖动平移（4px 死区，单击不受影响），双击/双指轻点在适应与 2×（不低于 100%）之间切换，手机双指缩放、单指平移；+/−/0 与方向键等价。平移夹紧在 16px 内边距内，图片不会被拖出画布；换图复位；减少动态效果时按钮缩放不过渡。弹窗不发送或删除附件，关闭恢复原触发点与草稿。手机采用全屏画布，图片操作至少 44px，输入附件的删除与预览分开命中。

站内 skill Markdown 链接在文档弹窗中阅读，保留完整原文复制和下载；不自动加载助手消息中的远程图片。弹窗沿用中性表面、正文的字号与行距，内部独立滚动，Escape 与关闭按钮均可返回原入口。公共原始 skill URL 保留，供 CLI 读取、复制地址和下载使用。

### 自动化视图（B-498）

自动化是侧边栏一级入口，紧接「团队」之下（同属"让多个 Agent 替我工作"的入口组），带 `--danger` 计数徽标表示需要决策的运行数；gate 关闭时整个入口不出现。列表与详情沿用看板的平面材质：1px 分隔、mono 机器层、`--accent` 仅表示 run 正在运行。「需要我决策」区用 `--danger` 标题与计数（与看板「等你处理」同一语义），为空时整块不渲染。列表按「定时」与「触发器」分组，组标题用 eyebrow mono。行内动词用短按钮（立即运行 / 暂停 / 编辑 / 知道了 / 再跑一次 / 取消运行），窄屏 979px 以下单列、coarse 指针 44px，600px 以下详情顶栏动词收成图标以保住自动化名称。

创建/编辑是整页表单而非弹窗（字段多、手机可滚动）：分「基本 / 触发 / 动作 / 限制」四组，每组一条 1px 顶线；触发器与动作类型用胶囊单选（选中为 ink 填充），字段下方一行 hint 或 `--danger` 错误，cron 字段的 hint 就是实时人话预览。输入控件 `--bg-2` 底、`--line` 描边，聚焦只改描边；手机 16px / 44px。「仅触发器」的详情页把触发方式当作内容展示：三条可复制命令，`--bg-1` 命令框 + 统一 CopyButton，不做高亮。未启用时显示说明性空状态，不报错。

### 内置工具行（B-499）

very-happy 自己注入的工具（change_title、copy_to_clipboard、open_preview、report_progress、`team_*`、`automation_*`、assistant 变体的 `sessions_*`/`terminal*`/`memory_update`/`journal_append`，以及 B-754 补齐的 `project_context`/`project_note`/`request_human`）在对话里不显示原始 JSON。识别不依赖运行器的命名形态：Claude 的 `mcp__happy__x`、Gemini 的 `happy__x`、Codex 的 `McpTool`+`{server,tool,arguments}`、pi 的 `other`+`piTool`/`rawInput` 与裸名共用一套身份（`components/tools/builtinTools.ts`）；只认 server 名含 `happy` 的前缀，其他 MCP 服务器的同名工具保持通用视图。

- 行内：工具名位是动词短语（Sans 600），detail 位是人话摘要（Sans，不用 Mono）：「委派任务 · 给 Codex · <目标>」「创建自动化 · <名称> · 每天 09:00 · Asia/Singapore · codex · <目录>」（触发/动作措辞复用上节 `automationPresentation` 的 `describeTrigger`/`describeAction`，不另写一份）「进度 · 待审阅 · <一句话>」。id 只显示前 8 位，长文本压成一行截断。
- 展开：参数按字段两列排列（窄屏单列），路径/命令/id 用 Mono，其余 Sans；验收标准等列表按项展示。结果区先给结构化摘要（任务 id 与状态、自动化的触发/下次运行、运行状态），再给指向 `/session/<id>`、`/teams/<id>?task=<id>` 的中性按钮（不用 accent；触屏 44px），原始输出折叠在「原始输出」下；自动化按钮指向 `/automations/<id>`，只有名称、还没有结果时不猜链接。
- 失败态用 `.tg-error` 直接显示服务端错误文本，不再显示结果摘要；流式阶段参数不全时只显示已到达的字段，完全没有参数时显示「等待参数…」，任何形状都不能崩。
- `change_title` 不再隐藏：Claude 路径仍由 `messageToEvent` 转成事件，Codex/pi/Gemini 路径显示「标题改为 · <标题>」一行。已完成的 `open_preview` 保持 B-452 的「文件预览＋可点击路径」行。

### 其他工具卡（B-754）

聊天流里不出现成块 JSON。所有运行器的同一种操作共用一张卡，识别只读数据、不改工具事件形状（`components/tools/toolPresentation.ts`，纯函数，带测试）：
