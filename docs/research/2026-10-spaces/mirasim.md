# Mirasim（mirasim.ai）产品调研

> 2026-10-17 子代理调研。来源：官=官网/docs；CL=changelog；群=skills 内试用群记录；【推】=推断。供 specs/2026-10-spaces-a2a.design.md 引用。

## 1. 定位 / 用户 / 形态 / 定价
- 一句话：「团队和智能体的协作工作间」——Claude Code、Codex 等 12 家 coding agent CLI 并排跑 + 团队共用协作空间。不是"数字员工"产品。
- 用户：个人开发者（免费工作台）→ 小团队（1 空间 5 协作席位 + 100 观察者）→ 企业（多空间）。
- 形态：桌面应用为主 + 手机 App + CLI/TUI + `ui-cli` + 8 个 IM 渠道；协作空间是托管运行环境（Linux 8c16G 或 Mac mini M4），不对中国大陆/港/澳开放；Alpha。
- 定价：Free $0 BYOK；协作版按环境 自带电脑 $0 / 轻量 $99 / 标准 $169 / 专业 $249，一次付 30 天不续费，到期空间内容清空；加席位 $30/人/月。

## 2. 概念模型
三层：工作台（本机）/ 团队（频道等）/ 云端（空间）。
- 空间（=一个服务端：本机、协作空间、接入的电脑、SSH 服务器）⊃ 工作区（目录）⊃ 会话（agent+模型+推理强度+可选 worktree，各有队列、记录、终端）；产物挂会话。
- 定时任务按工作区存 `.mirasim/schedules.json`。
- 事项 T-n（负责人/协作人/状态/子事项/里程碑/阻塞关系/看板）；目标（/goal → 目标空间）。
- 协作：频道（默认「大厅」）/私信/话题/会话评论。
- 助手 = 有名字的 agent（模型+默认工作区+skills+MCP，所有者/管理员建）；Matrix 官方协作助手（定时扫描、答未响应提问、@Matrix）。
- skills/MCP/连接器分全局与工作区作用域；额度分个人/空间；接口应用。
- 无独立"记忆/知识库"对象（pricing 提"共享记忆"但文档无章节，未披露）。

## 3. 人↔agent、agent↔agent
- 群聊 @助手 → 在空间开一条会话干活，结果回话题；助手提问只有 @ 它的人能答。消息「发给会话」当下一轮；会话某轮「评论」可 @人、「交给智能体」。
- 会话 owner=创建者，默认只有创建者能发；他人可看、「分叉一份给我」或创建者「共享给成员」后多人可发；一次只跑一个人的一轮，每轮署名；所有者可停别人的轮。
- agent↔agent：提示里 `@对话[会话]`，agent 获得 list/read_session、send_session_message、start_session 工具；投递规则按目标状态（空闲→新一轮；运行中支持中途输入→引导；否则缓存 5 min）；限流 30 条、链深 24 跳、乒乓熔断 12 条/5 min，本地账本 90 天。
- 审批点：目标「待确认→确认启动」；执行中只有范围/安全/权限/不可逆才「需要你」并显示阻塞数；「待验收」附证据；接管屏幕前须确认；侧栏「等你处理」收口。

## 4. 空间/团队
- 角色：所有者/管理员(占席)/协作成员(占席)/观察成员(100，免席，可 @助手不能驱动)；邮箱/链接/审批加人，访问记录。
- 共享粒度：空间级助手、共享 API key（成员看不到 key）、空间额度（不限/固定均分/定期均分/个人上限）、把自己电脑接入云端共享给成员。
- 他人 agent：可 @助手、可分叉他人会话；Git 身份按发起人由网关代填。企业多空间管理细节未披露。

## 5. 自动化
cron 定时（最短 10 min，错过不补跑，需服务端在线）；/goal 持续推进；目标空间由编排者拆任务分派、任务图+关键路径；Matrix 定时扫描；接口应用：令牌/公开访问，处理方式 直连/规则/智能体/本机服务，权限白名单，带签名事件推送、调用日志 30 天；`$eval` 评测。

## 6. 接入与 API
官网无 Tanka 字样；群记录：接回 Tanka「在推进、无时间点」；内部要求数据须留在 Tanka 体系内，否则不接入。开放面：接口应用（入站事件+出站 webhook）、ACP 供 Zed/JetBrains 连空间内 agent、`ui-cli`（UI 全部操作有 JSON 命令，配置树 `apply --dry-run`，`raw` 发协议帧）、`mirasim chat`、连接器走 MCP 官方注册表。公开 REST API 文档未披露。

## 7. 试用群产品层事实（10-16）
无自有 Harness，调原生 CC/Codex；核心价值=人与 agent 协作（空间聊天、分享 session、@成员/智能体接管）；空间内容属客户资产可导出；额度默认扣空间池。jojo 顾虑：协作上下文与聊天不在 Tanka 体系。外部争议（未核实）：上游额度不稳定、skills 安全指控。

## 8. 借鉴与短板
借鉴：
1. 「空间=服务端」统一抽象：本机/云/接入电脑/SSH 同一窗口，一行命令接入无头 Linux，状态 已打开/可连接/离线。
2. 会话互联协议：@会话 + 五个工具 + 按目标状态的投递语义 + 限流/跳深/熔断/账本。
3. 「等你处理」收件箱 + 队列四动作（发送/引导/插队/撤回）+ 停滞原因展示 + `ui-cli answer` 可脚本化批准。
4. 事项作为聊天↔会话↔待办的枢纽：从某轮「记为事项」、事项「新建会话」带用途、会话显示所属事项；目标空间只读规格侧栏（预期结果/验收标准/边界/未决）与最小审批点。
5. 面板即 CLI：UI 全部动作有 JSON 命令、声明式配置树 dry-run、每次模型调用五维账本。

短板：
1. 桌面优先非 Web，云空间封 CN/HK/MO，Alpha 不稳；共享会话一次只能一人驱动。
2. 额度经济复杂且带损；增长手法引发社区不信任。
3. 无自有记忆/知识库对象、无 Tanka 接入；聊天与会话数据留在 Mirasim 空间——与「数据进 Tanka」前提直接冲突。
